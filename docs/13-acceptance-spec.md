# 第一期接口规格与验收工作底稿

2026年11月20日。依据[产品决定与资源矩阵](10-product-blueprint.md)和[技术边界](11-technical-blueprint.md)。本轮采用合成业务资料。用户已确认暂无试点团队，企业人工基线和正式试点留待实际团队入选。以下为设计值及验收预期，执行结果栏从未运行开始填写。

### 规划按交付成果补齐能力

| 场景 | 验收条件 |
|---|---|
| 库里只有 Word 成稿助手，用户要求逐行交付 Excel | 自然语言和显式格式分别验证。缺口显示 Excel，原 Word 助手不进入执行清单。 |
| 模型返回的格式与成员显式选择冲突 | 保留成员选择。错误能力绑定、非 CSV 的分组汇总和提交不完整的待确认方案均失败，账户与项目中不留下额外调用或草稿。 |
| 已有适用修订 / Word 只是资料 | 再次处理清单时可直接推荐已发布 Excel 修订。读取 Word 后要求文本答复时，不能以 Word 排版充当答复能力。 |
| 资料、调用与交付 | 相同请求键和范围返回同一回执。更改格式重用同一键得到冲突。审核交付包中只有一份 XLSX，打开核对每行数据和以文本保存的编号 00017。 |
| 从上一版升级 | 历史建议可查看与重放，已排队的任务继续执行一次；新请求保存指定格式。 |

### 在执行中选择引文金额进行核算

| 输入与变化 | 执行及交付检查 |
| --- | --- |
| 普通成员提交结算单与标准，要求计算差额 | 规划推荐有界核算，人工采纳后固定资料版本。浏览器打开两份原件，核对算式及减法顺序，审批并下载结果。 |
| 两份收据求和 | 模型选取原文编号，由平台精确计算。样例 16.85 加 9.20 为 26.05。 |
| 只有标准或两份收据币种不同 | 记录需要补充的金额或币种。仅一次检索调用，结果中没有计算结论。 |
| 重复编号、负数、更大的金额 | 拒绝重复取数；同币种退款按负数计入。核对交付文件里的每一分。 |
| 检索后余额不足、重启、撤权和服务复用 | 在原运行恢复；可执行的任务总计两次模型调用，已撤权的任务保留一次。发布的服务沿用核算步骤，并从新调用方的资料取数。 |

### 核算待补件的普通成员路径

| 场景 | 可验收结果 |
| --- | --- |
| 发起人只提交标准，在网页版确认默认等待 | 首次检索后在原对话显示待补原件，刷新后仍可见。普通恢复操作无法跳过缺件。 |
| 补传多段文件 | 明确选中原句后才扩大本步可用资料。用已处理的提交标识重发，返回同一确认结果；引用能打开固定版本原件。 |
| 继续核算并排版 | 保留原运行和首轮成果，核算与 Word 排版各执行一次。独立打开交付包，核对文件哈希、审核人、引文范围、算式及 Word 中的金额。 |
| 预算不足、撤件、取消、重启 | 补件不授予预算。预算恢复时继续原步骤；核算前撤回资料时调用数保持一次。核算后、下一步发送前撤回资料时调用数保持两次，已取消的运行拒绝迟到的补件。 |
| 升级旧实例 | 旧版已受理的任务按原缺项说明完成。新建的网页项目可选择等待；发布服务保持原调用契约。 |

### 飞书单聊为原任务补件

| 场景 | 可验收结果 |
| --- | --- |
| 原文问答或金额核算缺少依据 | 发起预览显示等待规则。待补时，进度和任务卡显示步骤。确认文件之前，对飞书原件的读取次数为零。 |
| 选句并继续原任务 | 多段原件提交唯一原句。重复确认只接受一次，运行编号保持一致。验证剩余调用数和金额，浏览器审核后核对交付包引文范围及文件摘要。 |

| 升级旧实例 | 保留原发起令牌及已领取的附件读取任务，保持升级前的等待选项。 |

### 成员从对话制作工具 Agent

| 场景 | 验收要求 |
| --- | --- |
| 单团队成员补齐工具能力 | 对话内选择实际操作并创建草稿，关闭后能找回本人修订。其他成员不获得本人的快捷草稿入口，普通成员无法发布。 |
| 从附件列名配置汇总 | 核对带引号和逗号的表头。用另一份 CSV 明确试运行，缺列时阻止首次发布。打开最终工作簿对比分组金额、纳入与排除行数、币种和来源版本。 |
| 排版、清单与摘录 | 打开 Word 核对段落顺序，检查 Excel 保留前导零与等号开头的文本，摘录能核对来源版本。 |
| 项目内补能力 | 空候选且已有附件时，检验真实规划模型能说出缺口。在原建议中建工具草稿，过期提交不留下额外 Agent，原件样例验证并发布后才能采用，再单独确认项目执行。 |
| 连接器不符合文件声明 | 返回成功状态和文字，但缺文件、后缀或媒体类型错误、压缩包损坏或主文档入口不符时，新修订无法凭这次试运行发布。 |

### 从对话选用或补齐 Agent

| 场景 | 可验收结果 |
| --- | --- |
| 成员直接描述工作 | 一个可用团队时可直接发起，多团队且有有效默认时可在项目选项更改。归属不明确或已失效时保留输入，由成员明确选择。 |
| 从输入框选用推荐 Agent | 只显示有任务匹配且当前可用的发布修订，最多两个。合成样例检查草稿和未授权候选不出现。点选保留需求和附件，带入承担方及 Agent 修订。发送前无建项请求，收到方案后仍需授权执行。 |
| 普通成员从内置模板开始 | 从 Agent 列表打开模板，唯一可用文本模型时显示绑定修订。多个可用团队且无已选归属时先选归属。普通成员可试运行并申请发布，可把可用的发布版本带回原对话。由管理员从企业管理检查首次连通、配置规划模型和维护成员。 |
| 成员搜索并带资料选用 | 只可选择获准且已验证发布的修订，显示产出与承担团队。选择后保留需求和附件，方案固定修订及可读取资料版本，确认执行前没有项目运行。 |
| 成员描述新助手 | 能保存草稿、给出样例和预期、明确授权试运行。发布时校验职责与证据，发布后其他获授权成员能选用。失效修订无法通过直接建项绕过检查。填写草稿时遇到相同成果类型的已发布助手，可复用该修订或追加到原组合。复用不生成新草稿或消耗试运行次数。 |
| 从对话创建生图助手 | 保留原业务需求。按 PNG 选择可用模型，单独保存样图要求、验收人及标准。检查保存后调用数不增加。明确授权后生成可打开的 PNG，创建者与被指定成员可以在对话入口找回草稿。审核由指定成员完成，发布由有权管理员完成。核对发布前后可见状态，并在原对话选择发布的版本，取得已审核的图片。 |
| 成员组合 Agent | 同一承担方的组合中只展示一次费用归属。涉及多个团队时显示每步承担方；调整顺序后仍保留用户选定的项目归属。 |
| 遇到跨团队审批 | 处理人在我的待办按职责处理资源与费用，未加入对应项目时仅见编号。已转交或已处理的旧操作重新核权。 |
| 判断助手是否解决工作 | 合成回归检查入口、调用、审核与交付链路。业务质量和实际成本用企业样例、实际模型及人工基线独立评估。 |

从输入框组合两个已发布修订时，验收覆盖调序、移除、保留需求与附件、分别核对项目归属与每步承担方。带附件和无附件两条路径都应生成固定顺序与修订的待确认方案。执行后以第二步实际读取第一步成果、两个资源分别记账、两个版本均经审核并交付为准。无附件建项时任一步版本失效或权限已撤销，整个建项事务回滚。

## 2 渠道共用的业务契约（技术设计选择）

| 操作 | 调用方提供 | 成功响应与重复处理 |
| --- | --- | --- |
| 启动服务 | 已发布服务版本、输入引用、幂等键 | 异步受理返回202、run_id及状态地址。相同授权主体/目标/键/内容复用原运行，先重验当前查询权。同键改输入返回409 |
| 查询运行 | run_id、可选事件游标 | 200返回执行状态、等待原因、远端状态、审核/交付状态、下一步获准动作和费用状态。游标失效重取快照 |
| 暂停、继续、取消 | run_id、动作、expected_control_revision、原因、幂等键 | 受理后返回控制修订与远端停止状态。旧修订冲突，重复成功请求返回原受理记录 |
| 提交审核 | action_id、成果/清单及审核要求版本、expected_revision、明确决定、意见 | 写决定并返回decision_id。过期版本409，旧卡片展示新对象入口。业务事务写入后投递工作流 |
| 取交付 | delivery_id、成果项引用 | 校验当前授权、期限和内容可用性，返回固定清单及可下载项。缺权限与不存在对未授权主体采用一致的对象不可见响应 |

错误响应提供稳定类别、关联请求号、是否可重新提交及有权查看的处理提示。未登录401，已认证但无动作权403，对象不可见404，版本竞争409，参数错误422。已受理运行中出现预算或授权等待，由查询接口返回业务状态。任务执行状态与 HTTP 请求状态独立。

| 触发条件 | 从何处推进 | 持久化结果与界面预期 |
| --- | --- | --- |
| 运行受理，重复投递启动 | 已受理 → 排队 | 同一业务运行，工作流关联唯一 |
| 准备完成且可证明未发出 | 已准备 → 提交中 | 登记尝试与有效预占，再向远端发送 |
| 已发请求后进程退出 | 提交中 → 待核对 | 保留原ID和费用风险。查询有合法权限时才执行，不能证明未提交时禁止自动重发 |
| 结果落库后回执丢失 | 已完成 → 注入原结果 | 回读账本，在基准检查点消费一次，下游仅派发一次 |
| 人工等待时新版本取代旧稿 | 旧决定失配 → 等待当前版本 | 保留原决定、建立新版待办；超时只提醒 |
| 已取消后收到远端成功回调 | 业务仍为取消，远端可记录完成 | 按当前授权记录事实和费用，阻止候选交付及下游启动 |
| 恢复时依赖的偏好或资料被删除 | 原检查点禁止恢复 | 检查可证明干净的前序状态，或显示重建范围交有权人员处理 |

## 4 联合验证与证据填写

### 16.3 业务人员看到什么，以及何时能继续

运行页在受影响步骤显示“等待核对”，列出已发送操作、最后确认事实、可能新增费用、核对负责人、下次核对或到期时间。其他独立分支依已确认方案推进。对普通业务人员提供“查看影响”“补充凭证”“取消后续执行”；持有相应查询授权的服务身份或人员可用原渠道核对。飞书或 API 链回同一事项，通用消息不附原始输入、签名链接及凭据。

| 取得的证据 | 原操作与后续处理 | 验收时核对 |
| --- | --- | --- |
| 原任务成功且可取回成果 | 验证企业、资源绑定、原操作与输入版本，检查文件或正文完整性；按当前权限保存为候选，再交给该步骤约定的审核人 | 候选成果一份，原操作被消费一次；暂停或取消的运行保持其业务状态 |
| 明确未受理，或可证明该端点仍处于已验证的去重范围 | 按原绑定、内容与授权核验当前预算、控制修订、次数及时限；允许的恢复请求保留原消息身份。不同网络提交及其可见费用逐次登记 | 对照业务操作数、传输请求数、远端任务数和账单，分别报告 |
| 未知、查询过期、仅有扣费记录或多个可能匹配 | 保留原尝试、预占及已发生费用。供应商账单可证明支出，无法单独证明成果有效。到核对时限后交负责人处理；如需另行发起，显式说明原任务可能已执行，重新核验授权及预算并关联新旧记录 | 未获依据时自动新增付费提交为0；迟到的结果保留来源，不能覆盖新版本或触发额外交付 |
| 核对期间凭据撤权、任务取消或成果访问到期 | 撤权后停止相应访问。有权人员恢复同范围授权后才能继续查；原执行已取消时只登记远端事实及费用 | 查询、取正文、派发下游和采纳分别核权；业务终态及交付版本保持可追溯 |

以上判据分别可用培训材料生成、区域报表转换和视觉文件修改触发。实际外部动作和人工决定按角色分配；行业名称不参与状态判定。

### 逐笔调用费用导出

用合成部门发起一笔由其他团队承担的调用，调离发起人后核对历史归属。分别检查旧授权、仅汇总导出、仅逐笔导出、其他成员、管理员本人、撤权、重授及到期。手机或桌面浏览器提交用途并下载，验收文件名、字段及前后快照。先登记 0.000001 元，再最终入账 0.120000 元，核对逐行金额、账单行、待结算及同周期大盘合计。企业全域可查缺少承担方的调用。已有范围授权升级后默认关闭逐笔导出。分别以一万笔和一万零一笔检查完整生成及明确拒绝。隔离备份保留旧授权时，修复线上文件后仍须拒绝已撤回的财务下载。

### 企业单点登录与账号衔接

用真实身份源、合成成员和独立数据库走查。先让未绑定但邮箱相同的用户尝试登录，再从已有会话绑定，对比返回的成员编号和角色。用同一主体申请另一个成员，确认冲突后邀请仍可供合法成员核销；重复使用已核销的邀请须被拒绝。跨浏览器提交 state、取消登录后再提交、解绑后使用会话副本，分别核对结果。

### 项目资料全文与原件清理

使用两个独立项目，其中两份授权资料具有相同字节。由维护人对一份两版本资料执行回收、恢复和清除，分别检查每一版的原件、预览、检索、历史和方案引用。普通查看者与持有过时版本的维护请求均应被拒绝。恢复产生新资料标识，旧地址继续受限，回收前已经撤权的资料继续受限。删除已获独立分发决定的依据，核查相关交付重新等待核对及历史决定留存。

资料撤权前，普通成员在浏览器打开一项分配给两份成果的反馈。撤权后刷新权限，核对已打开的反馈、原始意见、处理记录、资料核对历史和版本说明。负责审核者仍可查看工作依据。重新批准交付分发后，普通成员可以读取获准版本，但工作意见继续受限。

另用三个历史运行核验实例管理员作为项目参与者时的实际业务职责。一人负责一份撤权资料，分别查看无撤权输入、仅有本人输入、以及同时有他人撤权输入的运行。将同一条意见分配到三个目标，再在同一次提交中另外分配一条范围较窄的意见。核验逐条正文、整份原文、冲突候选原件及预览、已采纳修订说明、修订 Trace 正文和带正文的导出。分别授予和撤回项目审核权，再移除项目成员资格。结构信息、其他独立意见和授权资料应按各自范围返回。

将隔离库中回收期限推进至到期，重启实际 Worker，检查文件系统、数据库、错误重试与审计结果。制造文件卷删除失败，同时验证其他摘要可清理。对同一摘要并发排队上传和清理，验证新上传仍可查到正确原件。将独立交付的文件另存为资料后清除，核对正式交付仍有效。隔离还原先前的归档，再修复线上可交付文件，原资料链接与被暂停的交付仍应受限。
