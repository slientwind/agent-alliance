# 预算控制数据库实验

合成币种为人民币，以十进制元记账。数据库内独立事务模拟各次提交。所有调用和供应商账单均为合成输入，测试仓库的业务接口留待联调。先固定以下判据。

| 情形 | 输入与预期 |
| --- | --- |
| 同额竞争 | 预算10元，两条独立连接分别申请7元。观察第二条连接实际等待第一条的行锁。提交后只有一条预占，余额3元 |
| 决定与回执之间中断 | 原尝试再次请求预占7元，保存的尝试ID返回原记录。不同金额复用同ID返回冲突，预占仍为7元 |
| 已知账单重复投递 | 同一供应商账号、同一账单行结算6元，双连接同时投递，实际6元、未结预占0元、余额4元 |
| 账户作用域与账单修正 | 第二个付费尝试产生同一账号下的另一账单行；相同供应商行号在另一账号独立计入。相同账单身份但金额不同标为冲突。显式修正单按差额入账并指向原行 |
| 多层预算 | 团队可用10元、项目可用5元，同一申请7元。项目不足，事务撤回，团队和项目预占都为0元 |
| 取消与未知结果 | 已发出的调用被业务取消，远端未确认。保持相关预占，待供应商结算后计实际，业务状态仍为取消。明确未提交的调用可释放 |
| 未知费用 | 只授予一个团队、一个操作类型、一个时段和一次提交机会。缺授权、过期、不同操作拒绝。并发下只消耗一次。授权时金额保留未知，供应商最终结算可超过团队预算，已发生费用如实登记并阻止新的已知付费工作 |
| 候选门槛 | 预算100元，已发生79、80、99、100元。80元起提醒。新申请2元分别为允许、允许、拒绝、拒绝。100元为候选停止阈值，超额不删除已有成果 |

补充比较分段账单。在两个独立预算中分别预占8元，限额各10元。供应商先确认2元，稍后累计确认5元。业务预期为阶段账单后实际2元、预占6元、可用2元，新申请7元被拒绝；最终账单只补记3元、释放其余预占，余额5元。保留把首笔账单视为最终账单的反例，并与显式标注阶段及累计金额的路径对照。
