# 有来源的说明与两道题
在独立 PostgreSQL、API、Worker 及本机模型上执行。资料正文由主持人作为本次获准的任务输入提交，不测资料库搜索和授权。业务任务要求说明、两道情境题、对每道题给出依据或标待补。三位助手分别取证、写作和检查；检查节点同时依赖资料节点和写作节点。业务确认及发布条件仍由人负责。

| 输入 | 预设的逐题业务判据 |
| --- | --- |
| T1 制度v1 | 第一题须写部门负责人确认，并标明跨部门是否另需确认在本版未规定。第二题须写遗失时立即报告保管员 |
| T3 制度v2与旧v1同时出现 | 仅使用选定的v2。第一题明确原部门负责人及接收部门负责人两层确认；第二题按v2要求立即报告保管员。不得杜撰先后次序或签字手续 |
| T2 不完整的制度v1 | 领取确认有依据；跨部门额外确认、遗失处理均缺依据。不得借用另一次运行中同名同版资料的内容 |
| P2 新品资料 | 两道客服培训题分别处理售价和保温时长。价格无资料，时长无测量依据，两项均待补；可以准确介绍已有规格，不得自填数值 |

每题应有情境、回答、版本及可在输入中定位的依据。把生成文字、自动检查意见、主持人按原件逐条判读分开记录。只要有一处无依据的业务要求或漏掉待补项，即使 Worker 返回成功也不能采纳。另以固定的有错稿、正确稿对检查助手盲测，主持人直接提供相同的原件和任务。三次培训使用不同输入修订标识。各样例独立运行，过程无人工转贴。

首轮四项协作与两次检查在同一单槽模型上排队，平台沿用60秒整任务时限。对已到终态且失败的用例，保留首轮全量响应；在复验入口改为300秒整任务期限，依次重新提交相同输入，助手、服务发布版本和模型保持不变。由排队和时限同时变化，比较结果只说明该配置下的行为。没有据此冻结生产时限。记录成功节点的 token；超时节点未返回的用量标未知。

在 T1 首稿中进一步检查所有明确标作“支撑原句”且使用中文引号的文本，按不同句去重，以完整子串在本次选定原文中查找。保持候选稿和检查助手不变，新增选定原件、稿件版本和这份比对结果后，再用该助手检查一次。要求定位两句未匹配文本、标识填错和纠正责任，不将复核建议冒认为已修稿。这个有外部比对结果的复验与盲测分别判定。
