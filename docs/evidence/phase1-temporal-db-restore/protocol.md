# Temporal 历史与查询库的备份配对

用原版 Temporal 服务、CLI、PostgreSQL 工具和本机内部网络。使用观察用的空任务队列，工作流在没有应用 Worker 时可受理信号与终止命令。所有标识和文本均为合成值。

1. 创建工作流 A 后等待列表出现。保存查询库的早期备份。
2. 创建工作流 B，向 B 发送信号并终止 A；等待任务列表与准确任务标识查询都反映这两项变化。关闭服务以停止写入，再分别保存历史库和查询库。
3. 将最终历史库和早期查询库恢复到隔离的新实例。观察两个工作流的历史、运行描述和索引查询，保留实际返回。预期至少一个列表项的存在性或状态与历史不同；真实行为以观测为准。
4. 用最终同一停写点的两库备份恢复到无源库依赖的环境，复核 A 的终态、B 的在途信号、两项列表及查询库扩展版本。
5. 单列 PostgreSQL 逻辑备份、真实 Temporal 查询与云上 RDS、OSS/KMS、平台业务授权的证据范围。此实验不测云上恢复时限。

第一次混合恢复后，查询列表自行追上了历史，与预期的可见差异不符。保留这次结果。追加对照：使用已恢复一致的服务，在没有新业务请求且历史库的即时任务表为空时停写，重新备份历史库，再与同一早期查询库配对。开服务前后均保存索引行，按业务标识查历史，连续两次检查列表，并记录观察时长。即便短时仍不一致，也不推断永久无法修复。
