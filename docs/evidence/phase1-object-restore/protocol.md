# 版本化对象恢复演练

环境为本机内部网络、专用容器和空卷，使用合成文件。预先指定撤除范围为一份资料的两个内容版本、一份逐行预览及一个含原文附件的旧交付包。已获准独立保留的说明文件和另一项目的同名资料作为对照。清理依据保存在业务快照之外，仅记录对象、归属、版本和处置理由。

| 阶段 | 操作 | 预期 |
| --- | --- | --- |
| T0 | 开启对象版本控制，上传两版原文及派生物，颁发指向原文旧版本的限时下载地址。停写后备份完整存储卷 | 可列出两个原文版本并读取其内容，登记对象及对照样例的摘要 |
| T1 | 普通删除当前原文，再分别从默认地址和固定版本地址读取；随后按清单删除全部目标版本 | 普通删除隐藏当前对象，固定版本仍可访问；彻底删除后固定版本地址应失效。记录预览与旧包独立可读性和对照结果 |
| T2 | 旧备份还原至另一个隔离卷，沿用测试签名身份和有效期，通过隔离测试路由访问原下载地址 | 重放前，原文、预览、含原文的包和已签发的旧地址均可能恢复可读 |
| T3 | 在恢复环境重放独立处置清单，再核对重复执行、指定版本读取和内容级保留 | 目标版本不可读取；两份保留对象可读且摘要一致；原备份另记其保留状态。只有全部核对完成才允许开放相应范围 |

本次模拟离线完整卷恢复。云上复制、备份到期介质清理、密钥轮换、应用授权和真实浏览器下载均需另外取证。

补测延迟写入。第一次恢复核对通过后，操作员把旧预览的同一份字节写回已处置的预览路径，模拟旧转换任务或迟到复制写入，保留新生成的存储版本号。按原物理版本号检查应仍显示不存在；按项目、资料修订、派生关系枚举并读取当前对象则能发现它。核实来源后清理该新版本，再核对两份独立保留对象。该步骤为人工注入，真实复制链路和转换服务须分别复测。
