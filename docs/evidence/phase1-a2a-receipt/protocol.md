# 已受理但调用方缺回执

本地既有发布镜像、独立空数据库、同一工作区与同一目标 Agent，使用内置 Mock 模型。协议 A2A 1.0 JSON-RPC。用现成命令行客户端发送合成文本，从干净的运行列表开始。

1. 首次 SendMessage 使用预先保存的消息ID。客户端丢弃响应正文；测试观察者独立从运行列表确认已受理，观察者信息不传给恢复请求。
2. 相同身份、消息ID、内容及目标发起恢复请求，使用新的 JSON-RPC 请求号；核对返回的任务、GetTask终态以及运行总数。预期一项运行。
3. 原消息ID变更内容，预期返回冲突且运行数不变。
4. 同样内容使用新的消息ID。预期生成第二项运行，说明换号重跑会改变行为。
5. 以未分配的任务标识查询，保存原始协议错误。客户端没有远端任务号时，不能将这次对照查询用作之前那项调用“从未受理”的证据。

该实验模拟调用方未保存回执，网络实际传输及供应商费用未注入。报告区分RPC信封、消息、远端任务和运行的身份。
