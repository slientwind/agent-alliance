## 一、面向非研发的 Agent 构建器专项对照

此前调研侧重 Agent 执行内核（OpenClaw / Hermes / OpenManus 等），而对“不懂 AI 的业务员如何用自然语言捏出好用 Agent”缺少横向体验拆解。下表对照 5 类主流产品：

| 产品 | 构建入口与交互范式 | 非研发友好度亮点 | 企业落地痛点 / 局限 | 对 Alliance vNext 的设计启发 |
| :--- | :--- | :--- | :--- | :--- |
| **ChatGPT GPT Builder** | **左聊右测 50/50 分屏**；左侧 `Create` 对话生成配置、`Configure` 查看表单；右侧 `Preview` 实时试聊 | 业务员全程聊天即可产出名称、头像、指令与开场白，心理门槛最低 | 接入企业工具需手写 OpenAPI Schema；试聊发现细节不对时难以做“结构化局部纠偏”；缺少企业审批与版本冻结 | **采纳“左聊右测 + 双 Tab”骨架**；增加**标杆样例文件反推规范**与**试聊指哪改哪**；用三层发布补齐企业治理 |
| **Claude Projects & Skills** | 极简知识文件区 + 简短指令 + 可复用 Skill 包；无复杂节点连线 | 强调“丢入参考资料（风格范例、制度模板）比写长 Prompt 更有效”；界面极其干净 | 偏向个人与轻量小组，缺乏全企业目录治理、跨团队权限与成本归因 | **引入「标杆样例驱动（Show, Don't Tell）」**：让员工直接上传 1–3 份过往好报告/标准表格，由 Meta-Agent 自动提炼规则 |
| **Coze（扣子）AI 建 Bot** | 自然语言生成人设、自动推荐插件与工作流；提供表单模式与画布编排模式 | 中文业务语义理解好，能通过一句话把零散需求转成结构化人设与开场引导 | 一旦涉及复杂任务，仍容易把非研发拉入“拖拽节点连线 + 变量映射”的半开发画布，普通员工上手即劝退 | **坚决不在非研发构建器暴露 DAG 拖拽画布与变量连线**；复杂多步协作由通用 Agent Loop + 意图化能力开关自动编排 |
| **Dify Studio** | 区分 Chatbot / Agent / Chatflow / Workflow 四种应用类型，面向应用构建者 | 调试日志、提示词变量、发布 API 与模型切换非常成熟 | 创建前必须先懂“Agent 和 Workflow 有什么区别”，本质仍是偏技术/产品经理工具 | **消除前置类型分叉**：业务员不需要先决定“建单 Agent 还是协作工作流”，只描述要完成什么工作 |
| **飞书 / 钉钉 AI 助理** | 嵌在办公 IM 中，以“选知识源 + 选现成办公技能 + 一句话指令”为主 | 与日常消息、审批、文档深度贴合，冷启动快 | 通用复杂任务执行力（沙箱计算、多文件对比、跨系统外部 Agent 接入）和细粒度成本/质量可观测较弱 | 借鉴其**意图化能力开关**（不暴露底层模型参数）与**IM 轻量触达 + 桌面深加工**的分工 |

### 关键结论（落地到 `18` / `21` 号文档）
1. **非研发人员擅长“给例子 + 挑毛病”，不擅长“从零写抽象 Prompt”**：因此构建器必须把**上传标杆文件**和**右侧试聊点选纠偏**作为第一公民。
2. **个人私有用“零摩擦”，企业上架用“严治理”**：旧方案要求个人建一个草稿都要选团队、配模型修订、等管理员审批才能用，完全扼杀员工自发共创；改为 `Personal（零审批）→ Team（自测通过）→ Enterprise（管理员审核）` 三级阶梯。

## 二、企业级全局模型网关与监控治理专项对照

你的需求要求企业管理员“配置全局模型资源为平台内 Agent 提供模型支持，配置其他服务资源，并监控企业内 Agent 的运行情况、Token 消耗、任务成功率等”。下表对照企业最常用的 4 类网关与可观测方案：

| 开源/商业参照 | 核心能力优势 | 架构与治理启示 | Alliance vNext 采纳边界 |
| :--- | :--- | :--- | :--- |
| **LiteLLM Proxy** | 统一 OpenAI 接口适配 100+ 供应商；支持模型别名（Model Group）、主备 Fallback、RPM/TPM 限流、精确 Token 成本表与虚拟 Key | **逻辑别名（能力档位）+ 供应商解耦**是企业运维刚需：升级模型或供应商宕机时业务侧完全无感 | 采纳**能力档位抽象**（通用/快速/深度/视觉/生图/向量）、**主备容灾 Fallback**、**Input/Output/Cached 精确单价表**与多级配额限流；根据已确认决策，**仅服务平台内置与员工自建 Agent，不向外部 Agent 签发平台代理 Key** |
| **One-API / New-API** | 国内部署极流行，对百炼、火山方舟、DeepSeek、智谱、本地 vLLM 等国内渠道适配完善；渠道权重与健康检查直观 | 国内企业自部署环境必须内置主流国产厂商的开箱模板，避免管理员手动拼 Base URL 与模型单价 | `/admin/models` 内置**百炼 / 火山方舟 / DeepSeek / OpenAI / Anthropic / Gemini / 本地 vLLM** 一键供应商模板与默认参考单价（管理员可覆盖） |
| **Portkey AI Gateway** | 细粒度路由策略、自动重试与熔断、语义缓存、按自定义 Metadata（部门/应用/用户）聚合成本与延迟 P95 | 监控不能只看“全公司一共花了多少钱”，必须按 **Agent / 部门 / 模型 / 延迟分位** 切片排障 | 预聚合统计表同时保留 `agent_id / source_type / model_id / team_id / user_id` 五个核心维度，支持大盘毫秒级下钻 |
| **Langfuse** | `Trace → Generation / Span` 瀑布流、Token 与费用拆分、用户反馈（Scores）关联具体执行轨迹 | 把**业务反馈（👍/👎、采纳、审核）直接挂载到 Trace**，才能回答“模型没报错但员工觉得不好用”的问题 | 监控大盘明确拆分 **执行成功率（技术）**、**轻量有效完成率（隐式正向行为+👍）**、**协作审核采纳率（显式签收）**；Trace 支持标准 OTel 导出（小企业直落 PG，大企业可对接 Langfuse/ClickHouse） |

### 关键结论：为什么必须引入“隐式正向信号”？
- 在企业真实使用中，80% 以上的 Personal Agent 对话属于轻量任务（查制度、改文案、做图表、整理纪要）。用户拿到结果后直接点击「复制」或「下载 Excel」离开，**主动点“采纳”按钮的比例往往低于 15%**。
- 因此 vNext 冻结为**双轨口径**：
  - **轻量任务有效完成率** =（执行无报错，且存在以下任一正向信号：`下载产物` / `复制回复` / `点击 👍` / `围绕结果继续深化且未触发负面重试或 👎`）/ 轻量任务总数；
  - **协作审签采纳率** = 经人工审核通过并完成交付的任务数 / 协作审签任务总数。

## 三、团队多人协同与 Skill/Agent 生态市场专项对照（增补）

### 3.1 团队多人协同 AI 工作空间对照

企业真实任务往往跨角色（如采购员收集报价 → 财务核口径 → 法务审条款 → 主管定标）。目前多数 Personal Agent（OpenClaw / Hermes / Manus / 个人版 ChatGPT）均为**纯单人会话模型**，分享只停留在“发一条只读链接”：

| 参照产品 | 多人协同做法 | 局限性 | Alliance vNext 差异化设计 |
| :--- | :--- | :--- | :--- |
| **ChatGPT Team / Shared Projects** | 支持共享自定义 GPT、共享项目空间与对话链接分享 | 缺少面向同一份任务的**角色分工（谁补件/谁审核/谁定稿）**、多成果并行审签与局部重跑 | 保留单人零摩擦默认；**一键拉同事进任务**，原生支持角色分工、右侧 Canvas 行内 `@同事` 评论指派、按版本审签与飞书协同同步 |
| **Claude Team Projects** | 团队共享知识资料与对话记录 | 侧重共享资料库与模板复用，不含多人接力补件、版本并发冲突保护和最终签收交付 | 复用 Alliance 已有强项（不可变版本、并发冲突保护、撤权即时阻断），通过极简的头像栈 + 评论/指派浮层把重协作做得像共享文档一样轻 |
| **飞书文档 / Notion 协同范式** | 同屏在线头像、划词评论、`@人` 自动发待办通知 | 缺乏自主执行的多步 Agent 引擎与跨外部 Agent 编排 | 借鉴其**“文档旁划词评论 + `@同事` 即派单”**直觉交互，直接嵌入动态 Canvas 右侧工作区 |

### 3.2 正规渠道 Skill 与 Agent 生态市场对照

| 生态渠道 / 参照 | 供给特征 | 企业直接使用的风险 | Alliance vNext 市场机制 |
| :--- | :--- | :--- | :--- |
| **MCP Official Registry / GitHub MCP 生态** | 工具协议标准化，覆盖数据库、文档、设计、研发与办公连接器 | 社区良莠不齐，存在停维护、过度索权、内网 SSRF 或凭据泄露风险 | **定期自动扫描同步元数据**，强制体检许可证、维护活跃度与所需权限；仅将经企业管理员审核的版本缓存为可一键加载项 |
| **SKILL.md 规范与官方/社区 Skill 仓库** | 轻量 Markdown 指令 + 参考样例 + 可选脚本，非常适合非研发按需装配 | 若允许在线动态拉取未经签名的远程脚本直接执行，极易引发供应链投毒 | 扫描发现后按 **SHA-256 哈希固化到企业私有对象卷**；运行时脚本强制锁在断网隔离沙箱内，员工可随时一键加载/卸载已准入 Skill |
| **A2A 目录 / Dify & Coze 插件市场** | 覆盖垂类专业 Agent 与现成行业模板 | 第三方服务质量波动大、费用黑盒且存在商业许可限制（如 AGPL/商业附加条款） | 市场卡片**显式标明许可证与来源认证**；新发现项先走「员工申请加载 → 管理员准入」，外部 Agent 仍坚持不走平台 Key 并做边界监控 |

## 四、非技术企业员工无引导可用性测试方案（补齐一手用户证据）

历史文档 [12-enterprise-research.md](12-enterprise-research.md#L26) 坦承尚缺真实业务员工的一手交互实测。在进入大规模前端重构代码开发前，建议直接用新版高保真原型 [vnext-prototype.html](uiux/vnext-prototype.html) 开展一轮 **5–8 人、每人 25 分钟的无引导走查**。

### 4.1 招募画像（严禁只找研发或产品经理测试）
- **4–6 名非技术业务员工**：行政/人事、采购、运营/市场、销售支持各 1–2 名（要求：平时偶尔用过豆包/ChatGPT/Kimi 聊天，但不懂 API、Prompt 工程或 JSON）。
- **1 名企业 IT / 运营管理员**：负责评估 `/admin` 模型配置、生态扫描源、服务接入与监控大盘是否看得懂。
- **1 名内部研发工程师**：负责评估 `/agents/connect` 外部 Agent 接入向导是否顺畅。

### 4.2 七个核心走查任务与观测红线

| 编号 | 测试角色 | 给受测人的自然语言任务单（不给操作步骤提示） | 核心观察点 | 通过门槛 |
| :--- | :--- | :--- | :--- | :--- |
| **UT-01 首次上手** | 非技术员工 | “打开系统，帮我核对这三份供应商报价并整理追问清单，然后把结果下载下来。” | 能否直接理解首屏入口、看懂思考折叠过程、在右侧 Canvas 发现乙缺有效期并完成补件与下载 | ≤ 3 分钟独立完成，全程无术语卡顿 |
| **UT-02 团队多人协同** | 非技术员工 | “这份报价表需要拉市场部周宁一起看，请邀请她进来并在供应商乙那一行 `@她` 核对预算，再完成审签。” | 能否一眼找到顶部「邀请协作」分配角色、在右侧 Canvas 发起行内评论与 `@同事` 并理解审签进度 | ≤ 2 分钟顺利完成拉人分工与评论指派 |
| **UT-03 切换外部 Agent** | 非技术员工 | “刚才那份合同条款你想让公司法务团队接入的‘合同风险审查 Agent’再看一遍，怎么找它并用起来？” | 能否自然找到 `@` 呼出或市场并区分内置/外部 Agent | ≤ 60 秒找到并发起调用 |
| **UT-04 自然语言建助手** | 非技术员工 | “你每周五都要整理部门周报，请自己做一个只给自己用的‘周报整理助手’，试跑一下并保存下来。” | 能否用左聊右测完成描述、上传标杆样例、通过试聊纠偏并一键保存为个人私有 Agent | ≥ 80% 受测人能在 5 分钟内独立建成且无需问管理员 |
| **UT-05 市场加载 Skill** | 非技术员工 | “去市场里找一个网上扫描出来的‘会议纪要转行动项 Skill’加载到你的助手里；再对一个未准入的外部调研 Skill 提交加载申请。” | 能否清晰区分「企业已准入（一键加载）」与「新发现候选（申请加载）」并看懂来源与安全标签 | ≤ 90 秒无歧义完成加载与申请 |
| **UT-06 研发接入外部 Agent** | 研发工程师 | “你们组用 Dify/FastAPI 写了一个内部报销问答 Agent，请把它接入平台先给自己团队试用。” | 能否在 3 步向导内选对模板、配通测试消息并理解“独立管理模型 + 可选回传用量”约定 | ≤ 3 分钟进入 `Beta 试用` |
| **UT-07 管理员治理与排障** | 企业管理员 | “把全公司默认主力模型切换到备用供应商，审批一条生态 Skill 加载申请，并找出近 30 天失败率最高或花钱最多的 Agent。” | 能否顺畅操作 `/admin/models`、`/admin/releases` 与 `/admin/monitor` 并准确解读双轨口径 | ≤ 3 分钟准确完成三项操作 |

### 4.3 实测后的收敛机制
- 任何**超过 2 名非技术受测人卡住超过 20 秒**的文案、图标或跳转路径，必须先在原型和 [21-vnext-uiux-spec.md](21-vnext-uiux-spec.md) 中修正，再进入前端编码，杜绝“工程师自嗨式复杂设计”再次进入主干代码。
