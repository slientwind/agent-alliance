## 一、面向非研发的 Agent 构建器专项对照

| 产品 | 构建入口与交互范式 | 非研发友好度亮点 | 企业落地痛点 / 局限 | 对 Alliance vNext 的设计启发 |
| :--- | :--- | :--- | :--- | :--- |
| **ChatGPT GPT Builder** | **左聊右测 50/50 分屏**；左侧 `Create` 对话生成配置、`Configure` 查看表单；右侧 `Preview` 实时试聊 | 业务员全程聊天即可产出名称、头像、指令与开场白，心理门槛最低 | 接入企业工具需手写 OpenAPI Schema；试聊发现细节不对时难以做“结构化局部纠偏”；缺少企业审批与版本冻结 | **采纳“左聊右测 + 双 Tab”骨架**；增加**标杆样例文件反推规范**与**试聊指哪改哪**；用三层发布补齐企业治理 |
| **Claude Projects & Skills** | 极简知识文件区 + 简短指令 + 可复用 Skill 包；无复杂节点连线 | 强调“丢入参考资料（风格范例、制度模板）比写长 Prompt 更有效”；界面极其干净 | 偏向个人与轻量小组，缺乏全企业目录治理、跨团队权限与成本归因 | **引入「标杆样例驱动（Show, Don't Tell）」与「官方交付母版绑定」**：直接上传过往好报告/公司母版，自动提炼规则并套用格式 |
| **Coze（扣子）AI 建 Bot** | 自然语言生成人设、自动推荐插件与工作流；提供表单模式与画布编排模式 | 中文业务语义理解好，能通过一句话把零散需求转成结构化人设与开场引导 | 一旦涉及复杂任务，仍容易把非研发拉入“拖拽节点连线 + 变量映射”的半开发画布，普通员工上手即劝退 | **坚决不在非研发构建器暴露 DAG 拖拽画布与变量连线**；复杂多步协作由通用 Agent Loop + 意图化能力开关自动编排 |
| **Dify Studio** | 区分 Chatbot / Agent / Chatflow / Workflow 四种应用类型，面向应用构建者 | 调试日志、提示词变量、发布 API 与模型切换非常成熟 | 创建前必须先懂“Agent 和 Workflow 有什么区别”，本质仍是偏技术/产品经理工具 | **消除前置类型分叉**：业务员不需要先决定“建单 Agent 还是协作工作流”，只描述要完成什么工作 |
| **飞书 / 钉钉 AI 助理** | 嵌在办公 IM 中，以“选知识源 + 选现成办公技能 + 一句话指令”为主 | 与日常消息、审批、文档深度贴合，冷启动快 | 通用复杂任务执行力（沙箱计算、多文件对比、跨系统外部 Agent 接入）和细粒度成本/质量可观测较弱 | 借鉴其**意图化能力开关**（不暴露底层模型参数）与**IM 轻量触达 + 桌面深加工**的分工 |

## 二、企业级全局模型网关与监控治理专项对照

| 开源/商业参照 | 核心能力优势 | 架构与治理启示 | Alliance vNext 采纳边界 |
| :--- | :--- | :--- | :--- |
| **LiteLLM Proxy** | 统一 OpenAI 接口适配 100+ 供应商；支持模型别名、主备 Fallback、RPM/TPM 限流与精确 Token 成本表 | **逻辑档位 + 供应商解耦**是企业运维刚需：升级模型或供应商宕机时业务侧无感 | 采纳 **6 档逻辑能力路由**、主备 Fallback、精确微元单价表；**仅服务平台内部，不向外部 Agent 签发代理 Key**；换模型前支持触发**黄金回归体检集** |
| **One-API / New-API** | 国内部署流行，对百炼、火山方舟、DeepSeek、本地 vLLM 适配完善 | 国内自部署必须内置主流国产厂商一键模板 | `/admin/models` 内置百炼 / 火山方舟 / DeepSeek / OpenAI / Anthropic / Gemini / 本地 vLLM 模板与参考单价 |
| **Portkey AI Gateway** | 按自定义 Metadata（部门/空间/应用/用户）聚合成本与延迟 P95 | 监控必须支持按 **Agent / 空间 / 部门 / 模型** 多维下钻 | 预聚合统计表覆盖 `space_id / team_id / agent_id / source_type / model_id` |
| **Langfuse** | `Trace → Generation / Span` 瀑布流，业务反馈关联执行轨迹 | 把**业务反馈（👍/👎、采纳、L2 确认）挂载到 Trace** 才能定位真实体验问题 | 拆分 **执行成功率**、**轻量隐式有效完成率**、**协作审签采纳率**，并叠加知识库命中率与 DLP 拦截统计 |

## 三、团队多人协同与 Skill/Agent 生态市场专项对照

| 维度 / 参照 | 行业现状做法 | 核心短板 | Alliance vNext 差异化设计 |
| :--- | :--- | :--- | :--- |
| **ChatGPT / Claude Shared Projects** | 支持共享资料库与项目指令，发只读会话链接 | 缺乏同一任务内的角色分工（补件/审核/终审）、多成果审签与离职公私分离交接 | **三级空间容器**（个人私密空间 + 团队共享空间 + 全企公共底座）+ 任务内一键拉人分工、Canvas 锚点 `@同事` 派单、岗位变动公私分离无感交接 |

## 四、企业空间、知识库检索与 ERP/CRM/电商系统打通专项对照（v1.2 新增）

围绕“企业内部知识 + ERP/CRM/电商活数据 + 个人/团队空间隔离”三大企业纵深能力，横向拆解 5 类代表方案：

| 参照标杆 | 核心长板 | 企业落地常见踩坑 | Alliance vNext 融合方案 |
| :--- | :--- | :--- | :--- |
| **Glean（企业级 AI 搜索与知识中枢）** | 连接飞书/Confluence/网盘等多源文档，**严格继承源系统 ACL 权限**，混合检索与权威度排序极强 | 偏“搜与问”，缺少隔离沙箱算表、套用公司母版生成正式交付件与多人审签闭环 | 采纳 **目录级增量同步 + ACL 实时复核 + 权威/失效版本权重 + 页码级高亮溯源**，并创新加入**「知识缺口与冲突雷达」**指导知识库补齐 |
| **RAGFlow / 企业文档解析引擎** | 深度版面分析（DeepDoc），保留 PDF 扫描件与跨页复杂表格的行列结构 | 仅做检索底座，缺乏业务术语同义词注入与业务活数据联动 | 在知识摄入层做**章节层级 + 表格结构保真切分**，并在检索前自动注入当前空间的**企业黑话与指标口径词典** |
| **Salesforce Agentforce / 金蝶·用友企业 AI** | 深度绑定 CRM/ERP 单据查询、客户跟进与业务事件触发，严格遵守用户行级权限（RLS） | 局限于单一厂商系统内，跨系统协同（如“抖店售后 + 金蝶库存 + 飞书制度”联合处理）困难；写操作一旦失控风险极高 | 提供**跨 ERP / CRM / 电商 / 工单的统一连接器与 MCP 抽象**：读走 **OBO 用户级行权限（L0 直达）**，写强制走 **L2 变更预览对比卡 + 幂等回执对账**，并支持业务事件 Webhook 主动唤醒 |
| **Snowflake Cortex Analyst / Cube 语义层** | 用受控业务语义模型（Semantic Model / Verified Queries）替代裸 Text-to-SQL，彻底消灭大模型胡编表名与算错毛利 | 配置偏数据工程师，缺少与日常办公对话及团队空间的自然结合 | 在「知识与数据」内提供轻量化**业务数据视图 + 统一指标口径字典**，AI 查数自动附带「取数口径说明卡」 |
| **Microsoft Purview / Nightfall AI DLP** | 在 AI 调用链路实时检测 PII（手机号/身份证）与商业机密，支持脱敏掩码或阻断外发 | 传统 DLP 规则笨重、误杀内部自部署模型调用 | **内外有别的精准 DLP 护栏**：内部自部署模型与断网沙箱按空间权限顺畅流转；仅在跨边界调用**外部第三方商业 Agent** 或公开外发时自动执行可逆令牌脱敏或 L2 拦截 |

## 五、非技术企业员工无引导可用性测试方案（扩展至 10 场景）

在推进前端深度迭代与大规模推广前，使用更新后的高保真原型 [vnext-prototype.html](uiux/vnext-prototype.html) 开展 **6–8 人、每人 30 分钟的无引导实测**。

### 5.1 招募画像
- **4–6 名非技术业务员工**：采购、电商运营、销售支持、行政/财务各 1–2 名；
- **1 名部门主管（团队空间管理员）**：负责评估团队空间知识库维护、口径词典、母版与缺口雷达；
- **1 名企业 IT / 安全管理员 + 1 名研发工程师**：评估连接器配置、模型网关、DLP 策略、岗位交接与监控大盘。

### 5.2 十个核心走查任务与观测红线

<a id="42-七个核心走查任务与观测红线"></a>

| 编号 | 测试角色 | 给受测人的自然语言任务单（不给操作步骤提示） | 核心观察点 | 通过门槛 |
| :--- | :--- | :--- | :--- | :--- |
| **UT-01 首次上手** | 非技术员工 | “打开系统，帮我核对这三份供应商报价并整理追问清单，然后把结果下载下来。” | 能否看懂思考折叠过程、在右侧 Canvas 发现缺项并完成补件与下载 | ≤ 3 分钟独立完成 |
| **UT-02 团队多人协同** | 非技术员工 | “这份报价表需要拉市场部周宁一起看，请邀请她并在乙那一行 `@她` 核对预算，再完成审签。” | 能否顺利拉人分工、在右侧 Canvas 发起行内评论与 `@同事` | ≤ 2 分钟完成 |
| **UT-03 切换外部 Agent 与 DLP 保护** | 非技术员工 | “把含客户联系方式与底价的合同摘要交给外部商业调研 Agent 分析，看看系统怎么保护数据。” | 能否看懂 DLP 自动脱敏/确认提示，不因生硬报错感到困惑 | ≤ 60 秒理解并完成 |
| **UT-04 自然语言建助手** | 非技术员工 | “你每周五要整理周报，请上传一份过往标杆周报，做一个只给自己用的私有周报助手。” | 能否在个人空间用左聊右测完成标杆反推、指哪改哪并零审批启用 | ≥ 80% 在 5 分钟内建成 |
| **UT-05 市场加载 Skill** | 非技术员工 | “去生态市场把已准入的‘财务深度校验 Skill’加载到你的助手，并对一个新发现项申请准入。” | 能否区分「企业已准入（一键加载）」与「新发现候选（申请准入）」 | ≤ 90 秒无歧义完成 |
| **UT-06 个人空间切团队空间与套用母版** | 非技术员工 | “从你的个人空间切换到‘电商增长运营空间’，用团队官方 PPT 母版生成一份退货复盘汇报。” | 能否一眼找到侧栏顶部空间切换器，感知到自动挂载的空间知识与官方母版 | ≤ 60 秒顺利切换并启用母版 |
| **UT-07 知识库 + ERP/电商联查与 L2 写回** | 电商/采购员工 | “结合公司退换货制度，查一下抖店退货异常 SKU 与金蝶库存，确认无误后批准生成 ERP 补货/处置草稿单。” | 能否点击知识页码溯源、看懂取数口径卡，并在 **L2 系统变更预览卡**上核对字段后确认写入 | ≤ 2.5 分钟准确核对并完成确认 |
| **UT-08 团队知识缺口治理与口径维护** | 部门主管 | “进入本团队空间的‘知识与数据’，查看员工最近问不出答案的高频知识缺口，并新增一条‘净毛利’计算口径。” | 能否在「知识与数据」三 Tab 间顺畅找到缺口雷达、同步状态与口径词典 | ≤ 2 分钟独立完成 |
| **UT-09 研发接入外部 Agent / 业务视图** | 研发工程师 | “用 3 步向导把内部报销 Agent 接入为 Beta 试用，并验证独立模型与边界观测。” | 能否快速选对框架模板、配通测试消息并理解不走平台 Key 的解耦规则 | ≤ 3 分钟上线 Beta |
| **UT-10 管理员网关切换、回归体检与离职交接** | 企业管理员 | “切换默认主力模型前先跑一次黄金体检集，然后为一位调岗员工完成团队空间资产交接（保留其个人隐私隔离）。” | 能否顺畅操作 `/admin/models`、`/admin/governance` 体检与 `/admin/members` 公私分离交接 | ≤ 3.5 分钟准确完成 |
