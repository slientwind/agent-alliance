### 从对话使用 Agent

团队管理收进按需入口。对话工具栏保留消息、资料和 Agent。有有效默认或唯一归属时可直接发起任务，多个归属且无默认值时由首次发送打开选择。主动更改从「我的工作区 → 协作与授权」进入。选到非默认归属时，对话中可直接核对；已选归属失效时保留消息和附件，重新选择后继续。Agent 面板优先提供搜索和创建。企业管理默认进入模型与 Agent，用户和运行监控放在同一分类，团队、部门及范围授权从高级设置打开。单团队实例按成员或应用查看企业用量，多团队才显示团队筛选。分类切换保留当次填写的模型配置草稿。[三种宽度的浏览器 Mock](evidence/rebuild-simplified-team/conversation-team-mock.json) · [合成数据集成](evidence/rebuild-simplified-team/integration.json) · [手机 Agent 入口](evidence/rebuild-agent-first-navigation/mobile-agent-picker.png)

### 在原步骤更换 Agent

普通成员可以在待确认方案中更换执行 Agent。候选按已发布修订的成果操作和输入约定筛选，原文核对与工具选择继续要求匹配的文本能力。更换时显示会使用新结果的直接和间接后续步骤。保存沿用项目的源版本、偏好和步骤依赖，并记录原方案版本、新方案版本及替换位置。新方案随后单独确认执行。

### 项目资料检索与引用

业务成员能从项目资料输入问题，核对命中的原文、版本和字符位置。方案发起人可显式引用整份资料，本页草稿保留原有步骤。新检索只使用当前可读版本。已固定的旧版可在授权内继续使用，资料变化时按成果处理影响。参与者能看原文，编辑方案仍按项目职责。

检索默认使用 PostgreSQL 原词和词句排序，企业可在实例内部启用固定 BGE 小模型；Worker 建立 pgvector 段落索引。真实 CPU 推理和真实数据库测得，既有 16 道合成题，词句首条引用或空结果达标 10 道，混合模式达标 14 道。漏召回的是两种描述遗失的口语问法。另行固定的 6 道活动与客服题，两种模式分别达标 3 道和 6 道。该指标只评价检索候选，助手任务执行使用本地 HTTPS 替身，正式企业质量及百炼向量适配仍待验证。[既有题混合模式](evidence/rebuild-source-retrieval/hybrid-existing.json) · [新增题](evidence/rebuild-source-retrieval/hybrid-transfer.json) · [词句对照](evidence/rebuild-source-retrieval/lexical-existing.json)

团队内可查看创建人、当前维护人及交接事件。依据向该事件的处理人与接任人显示。「项目引用与交接记录」列出本人仍有项目访问权、且当前方案实际固定此规则的项目及版本。交接不触发规则发布、到期续期或项目重跑。已受理项目沿用其固定版本并按当前使用条件检查，后续新方案采用当时生效的发布版本。

从旧库升级时，创建人仍在团队内的历史规则由其继续维护，创建人已离开团队的规则进入补任待办。旧 API 按创建人授权复查；启用交接前须切换到识别维护人字段的 API。已发生交接的实例回滚时也须保留这项授权判断。

多团队走查发现预算管理页按团队名称选中首项时，兼任管理员的预算负责人可能先看到空面板。预算页现保留上次在当前面板内的选择，首次进入优先定位待审批团队，其次是本人负责的默认团队及其他负责团队，其他团队仍可手动切换。

培训制度样例通过手机网页接受维护职责。浏览器只展示接任人获准查看的引用项目，已受理项目按 v1 完成审核交付，新方案固定 v2。测试通过隔离库推进复查日和到期日，验证待办随职责转移、交接保留期限、过期的 v2 限制使用，已交付 v1 仍可查阅。测试还实际办理了创建人离职、团队撤权与重新入组，以及管理员在维护人临时停用时发起补任后的权限重查。[手机交接页](evidence/rebuild-rule-maintenance/rule-maintenance.png) · [执行回执](evidence/rebuild-rule-maintenance/rule-maintenance.json)

## 资料换版、撤权与成果依据核对

在「项目资料 → 资料版本与引用影响」可查每个版本的原文件名、作者、时间、可读性及大小，以及本项目中固定该资料的方案、运行和成果。资料维护者选择新文件或撤权后，先查看受影响成果，再确认操作。旧版本按原编号取回；部分旧库中的文件名从未记录，这类版本显示“历史文件名未记录”。项目原件撤权后，各版本的原件读取均需遵守当前授权。

当前运行把方案固定的项目资料作为各制作步骤的共同输入。字节及处理结果相同的改名保留原审核；资料内容、提取结果、媒体类型改变或访问撤销后，系统列出相关成果，由审核人判断具体影响。可读取的文本提供按行对照，从首个差异行展示到末个差异行。较长片段标明截断，可取回固定版本全文核查；专业格式可在外部工具中比较。撤权后对照入口和原件读取同时受限。每次决定绑定资料的采用版本、观察到的版本、撤权状态和成果版本。选择沿用需写明依据，要求修改会建立现有审核流程中的必改项。修订产生新成果版本后须重新核对。原审核记录仍可查阅；未处理的资料变化会阻止确认交付。处理意见本身不会启动模型调用。核对新版不会替换在途方案的模型输入。审核人可以人工修订、回传新文件，或把必改项交给负责该成果的 Agent。在这条资料核对意见下，改稿表单分别确认本次调用和新版资料的使用。默认沿用原方案引用；主动选择新版只影响这一次改稿。模型与工具读取同一组固定输入。派发、恢复和采纳时检查资料是否仍可用，授权的新版再次更新或撤权时须重新核对。

新交付包把资料采用版本、交付时观察的版本、访问状态与当前成果的核对回执固定在 manifest.json。交付后资料变化会在项目内提示，历史交付清单保留当时记录。每份资料下的 revisionInputs 列出已采纳的单步换版记录，包含具体成果版本、方案资料版本、本次选择、授权人和反馈。后续人工编辑仍可沿版本记录追溯。升级前已封存的交付没有当时的资料状态快照，系统不会用今天的状态补写。已分发副本的追回、已交付派生内容的访问调整、永久清理与备份清理仍属独立能力。

合成培训资料从一小时更正为两小时。审核人通过网页对照原文，保留未涉及时长的摘要，要求另一份成果改稿并审核 v2。资料随后更新到 v4 并撤权，已封存包仍保留审核时见到的 v3 及两项核对回执。合成模型只在收到 v3 正文、且输入资料中没有 v1 时返回预期讲义。另一项改稿在派发前被预算阻塞；先更新所选资料，再撤权，两次恢复均未增加调用或产出新稿。另一个待交付项目在网页撤权后须就独立核实依据重新记录决定，才可继续确认交付。[文本对照与审核](evidence/rebuild-source-impact/source-assessment.png) · [执行回执](evidence/rebuild-source-impact/source-impact.json)

## 缺少远端编号时的调用核对

项目发起人可在调用记录中登记核对依据；局部改稿还允许仍具项目审核资格的原调用发起人办理。继续等待会留下核对人、依据和时间。原请求返回错误、外部执行结果仍未知时，负责人可明确接受重复执行和收费风险，授权该步骤新增一次调用。已取得任务编号的调用沿用原任务查询。仅留有提交意图时按本次调用保存的执行时限和核对时限推进，核对过程中可等待或取消。核对时限已过且仍无回执时，负责人可根据核对依据显式承担风险重新执行。

新调用在原运行中重新检查当下的资料、资源、角色和预算。只有新调用实际派发，才登记新的调用批次和独立费用记录。原调用继续保留未知状态，可按原账目核账。运行 Trace 和 OTLP 接收端能区分同一步骤的不同调用；其他步骤及既有成果的版本保留。局部改稿成功后，审核人仍需复核新版。

合成项目验证了两步讲义的第二步响应丢失，新增调用先被预算阻塞，恢复后交付。随后局部改稿也遇到结果未知，原发起人的审核资格收回时无法授权，恢复后才可重新执行。最终交付固定第一步 v1 和第二步 v2。[浏览器核对界面](evidence/rebuild-call-recovery/call-recovery.png) · [运行、审核与交付回执](evidence/rebuild-call-recovery/call-recovery.json)

## 发送后进程失联与迟到回执

运行时在派发前保存两个时限。执行超时后检查是否仍缺少原回执，核对窗口结束前保留等待和取消入口。外部 Agent 采用固定修订的配置；模型和内置工具采用适配器执行时限，再留 900 秒核对。升级前的在途记录采用 120 秒历史活动时限和 900 秒核对时限。时限经过本身不会新增调用或费用。

重新授权与原回执提交按同一运行串行处理。原结果先到时会唤醒工作流，按当前条件复用。重新授权后到达的回执关联原调用，可以核对状态、时间和结果指纹；该步的负责人还可下载 JSON 回执，费用权限单独决定是否显示用量。业务成果沿新调用继续审核，不会被迟到的正文或文件替换。迟到的远端任务编号供人工核查，从该历史编号继续轮询或取消仍待实现。

合成场景在隔离数据库中推进调用时间，使用实际 Worker 进程和 Temporal 验证恢复。重新授权前取得原结果的任务仅调用一次。重新授权后才到达的结果保留原回执，两次调用可以分别核对。另一次在模拟供应商收到请求后强制终止 Worker，重启后仅派发一次已授权的新调用。并行任务中，外部 Agent 仅接收一次发送请求，受影响的模型步骤单独恢复，最终两份成果均完成审核。[浏览器核对界面](evidence/rebuild-submission-recovery/submission-window.png) · [四组运行与交付回执](evidence/rebuild-submission-recovery/submission-recovery.json)

## 交付后的关联修订

有项目审核权限的成员可从最近一次交付选择一项成果，登记具体修订要求。修订绑定项目修订号、交付批次和成果版本。意见进入原项目的修改待办，人工编辑、外部文件回传、另行授权 Agent 改稿和反馈转交沿用审核流程。需要修订的版本及其下游重新审核，独立分支保留原审核；负责该意见的人复核当前候选版本，再由当前最终确认人交付。已失效的临时访问不会因开启修订恢复。

网页、Open API 与 ZIP 使用相同的批次序号及相邻批次对照。可展开两次交付的正文或文件摘要，分别下载原件，区分内容变化、文件替换、上游引用换版及沿用项，并核对接收人说明的变化。下载先核验当前项目成员或原服务调用身份。每个已确认批次的访问地址保持固定，正在修改的成果不会进入先前批次。首次交付迁移为第 1 批，旧版未带批次的链接继续读取这一批。

## 交付确认后资料撤权

资料在确认交付后撤权，依赖这份资料的已交付成果进入待核对。项目成员看到受影响的资料、成果版本、交付批次、可处理人和当前分发状态。资料创建人或项目发起人逐项填写判断依据，处理历史保留操作者和时间，并校验决定的修订号。审核身份本身不授予分发放行权。多个来源或多个成果有未解决事项时，整批维持暂停。只影响原资料引用、成果已有独立依据时，可以恢复同一份已确认包；结论失效或内容传播受限时，原批保持暂停，可另行提交修订。

普通接收人受限时能查看交付存在及固定版本，无法通过清单正文、ZIP、成果版本原文、受限文件原件或预览读取。项目审核人和相应资料负责人在工作区核对内容，正式交付出口统一核验分发状态。正在准备的 ZIP 在发送前再查身份及当前限制。修复稿须完成业务审核和对应的分发判断后重新交付。撤权发生在第一次交付前的项目，沿用原有的逐项资料依据复核。已下载的副本、项目成员此前自行复制到外部的内容由接收方处理。

网页在项目和成果待办展示当前限制，飞书绑定成员可查询项目待办，服务调用方可续读撤权及分发处理事件并重新查询各批次状态。跨渠道主动推送及实际送达仍待验证。

在 014 版合成库的独立副本上完成升级。旧交付缺少单独的资料回执时，平台从已交付成果的运行和固定方案推导引用关系。撤销其中一个来源后，两份历史交付中仅引用它的批次进入待核对，另一批保持开放，原交付的资料回执未被补写。

## 文生图资源与 PNG 成果

团队按修订选择文本或 PNG 操作，历史模型按文本读取。规划助手和默认文字助手仅接受文本修订。PNG 候选按实际已发布修订参与推荐，方案确认前展示原生预览、整图重生成及外部 PNG 修订回传三种操作。连通检查、Agent 试运行、项目制作和用户授权的改稿分别计入对应调用。图像回执不产生文本 Token 数。同步图像调用的执行窗口为 10 分钟，未取得回执后另有 15 分钟核对窗口。项目方案和网页服务都展示图片的实际修改方式。下游文本步骤接收尺寸摘要，图像内容须由审核人实看。

图像适配器使用同步兼容接口，一次要求一张内联 PNG。原件大小上限为 6 MiB，宽高分别不超过 8192，像素总数不超过 4194304，技术检查会完整解码。企业给 Agent 配置至少一项具名业务验收，验收人查看实际文件后提交结论。项目可重生成整图，也可由审核人上传 8 MiB 以内的同格式精修稿。新版本须重新审核，交付包固定原件和摘要。

真实供应商账号的业务质量、耗时和计价仍待验证。参考图保真、遮罩局部编辑和异步取图各自需要接入和验收。[百炼图像接口](https://help.aliyun.com/en/model-studio/qwen-image-generation-and-editing-api-reference)
