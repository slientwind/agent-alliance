# Agent Alliance 使用手册

本仓库按[第一期产品方案](10-product-blueprint.md)、[技术方案](11-technical-blueprint.md)和[对话工作区设计](14-uiux-design.md)重新开发。一家企业运行一个实例。业务事实存储在 PostgreSQL；Go API 与执行 Worker 分别启动，Temporal 承担持久化调度，Eino 承载 Agent 调用。前端使用 Node.js、TypeScript 和 React。

## 从对话使用 Agent

新并行任务里的某个步骤可能显示「待核对执行条件」。卡片显示绑定的 Agent 修订和原因。独立步骤仍可在授权及预算范围内继续，依赖该步骤的工作等待。请按卡片提示恢复所需的权限、证据或预算，再由项目负责人点击「核对执行条件」。复查沿用原方案。仍有缺口时会显示新待办。飞书的进度提醒可回到原项目，签名应用可在原成员委托下提交复查。

接受企业邀请后即可从「新对话」开始。只有一个可用团队，或有默认团队时，系统带入项目归属。加入多个团队时，也可以先写需求、附资料或选 Agent。选用 Agent 会带入这次任务的承担团队。临时移除或用完这个 Agent 后，普通对话继续使用之前选定的归属；已失去访问权时重新选择。直接发送自由描述且归属仍待确定时，再选团队并发送。也可以在发送前打开「我的工作区 → 协作与授权 → 更改项目归属」。模型配置、用户管理和企业监控由管理员在「企业管理」中处理。

在首页写下想完成的工作，可以附上资料。匹配度足够的已发布助手会显示在输入框旁。点选后保留原需求和附件，带入 Agent 版本与费用承担方。也可以打开「Agent」按名称、任务或成果格式搜索。选中后核对方案再执行。缺少合适的助手时，点「创建 Agent」沿用并修改刚写的需求。遇到同样能完成任务的已发布版本，可直接选用或加入当前组合。文本助手用一条样例及预期结果试运行。生图助手选择「图片（PNG）」，填写样图要求、验收标准和看图人。保存要求后，单独授权生成样图。创建者和指定验收人可从同一入口的「我的生图草稿与验收」继续处理。通过检查后由管理员发布，成员就能在同一入口复用。

试运行结果不符合要求时，在「我的文本草稿」打开原 Agent，展开「调整 Agent 职责」保存新修订。从「试运行记录与回执」点「沿用这条样例」，核对输入和预期后重新授权。项目内补建的模型 Agent 可在「验证并发布此草稿」中直接调整职责和绑定版本，沿用该缺口的样例。工单编号等只允许一种完整输出的任务，可在创建文本草稿时勾选团队共享的逐字验收。管理员发布验证通过的修订后，继续原对话。

业务人员也可以从「创建 Agent」选择具体工具。例如把已确认的正文排成 Word、把清单逐行写入 Excel、按金额列分组汇总，或从原件摘取正文。做分组汇总时，可从当前对话的 CSV 附件读取列名，指定分组、金额、筛选条件和单位。草稿可在同一入口找回，用单独填写的样例试运行、打开原件。管理员发布后，回到草稿点「查看发布状态」即可将这个版本用于原对话。资料正文在用户确认范围后用于项目执行。

规划助手提示缺能力时，在待补能力中选择「用内置工具补齐能力」。草稿归属当前项目所在团队，可在项目内验证样例、查看原件，待管理员发布后采用为待确认方案。[普通成员实例](15-rebuild.md#从对话和方案缺口创建工具-agent)

需要多个助手接力时，点「组合 Agent」依次添加。例如先整理访谈记录，再核对原文依据。可提前或移除步骤，在原对话保留需求与附件。各步骤显示版本和费用承担方。跨团队时可选择项目归属，调整顺序会保留该选择。后一步会读到前一步返回的文本；图片或文档原件在审核时查看。发送后可在待确认方案内调整并行或依赖，再授权执行。

新运行中，普通文本步骤引用多项成果时，组装后的文本输入最多为 128 KiB。空间紧张时，保留执行要求、规则和已选资料，上游短结果优先完整保留，长结果按各自份额逐字摘取首尾。发起人可在调用详情核对哪些步骤用了摘录及采用的版本。模型提示依据不足时，可回看相应成果后缩小资料范围或拆分步骤。应用查询可读取 `steps[].upstreamExcerpted`。Office 制作、汇总和原文问答沿用各自的输入约定。

在「Agent」输入要完成的工作，例如「请根据客户访谈提取需求，并注明原文」，可按任务词找到名称或表述不同的已发布能力。单独输入 Word、Excel 或 PNG 会按实际产出筛选。创建前会提示产出相同且有共同任务词的现成 Agent，列出命中词、发布修订和费用承担方。选择后可以编辑任务，再提交。

支持流式回复的文本步骤会在对话中显示本人发起的草稿。连接中断时任务继续运行，网页重连后接着显示缺失片段，或从当前授权快照恢复。生成中断时可核对留存的草稿。正常完成后从原任务查看候选成果。需要停止任务时，在运行区选择取消。

### 为指定 Agent 保存个人偏好

在「我的工作区 → 个人偏好」填写偏好并选择「适用 Agent」，再在需要的方案中明确采用该偏好修订。可选择接收对话要求的已发布 Agent。实际执行的 Agent 与范围匹配时才会直接读取它，备用 Agent 只有在被选中后才会使用其适用偏好。本次任务的要求和团队规则优先。

纠正个人偏好后，在方案中重新选用才会采用新修订。首次调用时已失效的限定偏好会从输入省略，已使用过它的候选需要按原依据复核。分享 Agent、复制模板或发布服务时，个人偏好由下一位使用者自行配置。

偏好到期或被撤回后，依赖它的暂存草稿和补件内容会在复核授权时收起。仍具备条件的独立步骤继续显示。平台会清理失效的临时内容，模型调用记录、用量和已经形成的成果按各自的权限与期限管理。

未审核候选若因已采用的个人偏好失效而显示「待重做」，项目发起人可以从原任务核对受影响的步骤、可沿用的成果和调用上限，再授权重做。重做略过失效的原偏好，仍有效的原修订继续适用。此前已审核的版本可在成果历史中按原权限查看。

### 核对规划引用的早期消息

长对话规划保留最新业务消息，并根据当前提到的编号或相关词组查找同一项目的早期用户消息。打开规划建议里的「查看本次使用的早期相关记录」，可核对实际采用的摘录，并点「查看原消息」跳回上下文。旧约定有变化时，在输入区写明本次适用的要求，再请助手规划。本次历史查找使用同一笔规划调用授权。

### 让方案对得上交付成果

协作方案中每个步骤在自己的前置成果齐备后继续。一个外部任务正在后台等待回执时，其他已具备条件的步骤可以推进。需要合并多项成果的步骤会等待所有相关成果。暂停、取消与人工核对从当前运行的控制入口处理。

在对话中写清楚要拿到什么，例如“把盘点清单逐行写成 Excel，保留前导零”。规划建议会列出识别到的交付格式。已有助手只会把正文排成 Word 时，可以在原方案里补建清单助手。要固定交付格式，可在授权规划前展开「指定交付文件格式」并勾选一项或多项。已有符合本次工作的修订时，可直接复用。上传 Word 请助手读原文作答时，输入文件和需要的文本答复分开判断。例如要求用同一份领用清单制作 Word 和 Excel 时，平台分别核对两种成果的制作能力。原件已备好且两步都是排版时，可勾选「各文件分别使用已选原件制作」。两个版本独立审核，一并打包交付。

### 带着问题查资料

长对话会保留最新一条用户消息，并选取近期对话和部分早期要求供规划使用。看到摘录提示时，可把影响交付的限制或更正补写在最新消息里。旧助手答复依赖的资料需要处于本次所选的可读版本范围内，才能继续作为规划上下文。

也可以直接附上资料并说明要交付什么。发送后勾选本次允许使用的文件，授权一次规划调用。问“规程规定由谁核对铅封”时，助手可推荐查原文和引用；问“把两份区域流水汇总成 Excel”时，助手可推荐计算工具。采纳建议后核对资料版本、步骤和费用，再执行。助手追问后可以继续在原对话补充，刷新仍保留上次选择的文件范围。

选择一个已发布的文本模型 Agent，附上资料，在对话框勾选「检索原文后回答」。例如上传交接规程后问“温度超过多少时应暂停接收，由谁核对编号？”方案列出检索与回答两步，分别计费，最多两次模型调用。Agent 先根据问题选词，由平台在固定版本的资料中查找原文。找到依据后，Agent 可以回答、请求补充，或根据首轮引文追加一次本地检索。首轮查不到引文时默认生成补充资料的提示。确认方案前勾选「原文不足时等待我补件」，可在原对话选择补充资料中的一段原句，用已授权的第二次调用继续回答。审核人可从引文打开对应版本的原件，核对回答和依据后确认交付。在组合方案中也可为单个文本步骤勾选检索，再添加 Word 助手接收回答和引文。

企业启用了本地语义检索后，首轮选词无匹配时，Agent 可按中文问题补查本次确认的资料版本。刚上传的资料若只剩少量片段待索引，可直接在本次任务中使用。例如把「活动现场没法用机器签到」匹配到制度里的「启用离线纸质名册登记」。待索引片段较多且仍查不到依据时，任务会保存选词，在两分钟内等索引就绪并自动继续。自动等待到期后，在原对话点「重新核对原资料」即可复查。已开启等待补件的发起人也可直接补充原句。审核时可以查看原件与引用，历史版本仍可按原词检索。

新并行任务会按步骤显示索引等待。缺少索引的原文问答可等待，其他就绪步骤继续。索引到期时从该步骤重新核对，已上传的原件和已授权的调用额度沿用本次任务。飞书「进度」和任务卡会列出待索引的步骤，手动复查从卡片链接进入原任务。Open API 从 `indexWaits` 取待办，以 `recheck_source_index` 提交 `step`、`waitRevision` 和当前控制修订 `expected`。早先的运行级 `indexWait` 使用 `resume`。

在原文问答的方案里勾选「补查有新依据时续答」，会在方案费用和调用上限中预留一次额外答复。续答需要补查或经办人提供可核对的新原文。已有答复或没有新增依据时，页面沿用原答复或缺项提示，并记录跳过。后续步骤和审核使用最终候选。

当方案同时允许等待补件，并且模型指出仍缺哪段资料时，发起人可在原对话查看问题。选择一份未绑定的原件并确认一处原句后，任务使用原方案预留的下一次调用。飞书「进度」可定位补件，Open API 通过 `receiptRequests` 给出原步骤、续答步骤及待办修订。上一轮依据已失效时，须回到原任务核对。

如果同一问题需要核对多个证据点，可在上述选项下再勾选「允许再次核对并补查」。保存方案并确认本次最多四次调用。复核只在首次补查取得新依据时运行，可直接回答、指出具体缺项，或再查本次获准原件。再次补查仍有新增原文时才使用最后一次续答。网页、模板和已发布服务都显示这些阶段，实际费用按发生的调用记录。

新任务遇到多个不同的证据点时，原文问答可在本次获准的原件中分两至三组补查。网页显示当前组及核对状态，Open API 通过 `lookupBatch` 返回当前组和本次计划组数。各组共用原来的模型调用，结果在全部查完或达到六条新增引文时汇总。断线或 Worker 接管后按原任务继续。若各组均无新增依据，可查看原引文或按提示补件。

新任务补查原文或核算引用金额后，网页可能短暂显示「已完成补查，正在核对依据」或「已完成核算，正在核对依据」。此时平台已保存待核对的结果。Worker 接管时复用该记录，核对当前权限和原文后才生成候选。中途撤权或取消时，保留原调用账目并停止提交受影响结果。Open API 在进度和运行事件中使用 `checking_observation` 表示这一阶段。

核对多份原件时，可以在工作目标中指出要分别检查的文件与条件，例如分别找到甲、乙报价的有效期。Agent 可按指定原件查找短词，也可读取获准引文的相邻原句。补查直接形成候选时，候选逐项列出新依据及未命中情况。仅限一条原句的补件按原授权使用。开启「依据新增原文继续作答」时，后续回答使用新增的可核对依据，调用计入已确认的额度。

对话附上 CSV 并明确希望根据本次目标选择一种汇总口径时，规划助手可以推荐同团队中金额、过滤和单位一致的候选。查看建议里的版本和字段后，可以直接采纳再确认执行。手动配置时，在「拟定协作方案」添加可独立开始的文本 Agent，再添加引用它的汇总 Agent。引用 CSV 后，展开汇总步骤的「允许 Agent 在两个汇总工具中选择」，选同团队的另一个已发布汇总工具。确认前打开「查看两项汇总口径」。Agent 只根据本次目标和表头选择，所选工具生成 Excel。若需要人工选择，可在原对话点选一个候选并继续。发布为服务后，每次调用附本次的 CSV。

文件制作也可预先授权两个候选。以采购简报为例，添加「选择简报工具」「编写正文」「制作 Word」三个步骤，让前两步可独立开始，Word 步骤引用两者。展开「允许 Agent 在两个文件工具中选择」，选一个同团队且输入约定一致的已发布 Word 工具，并指定负责选择的文本步骤。选择步骤根据任务要求、原件名称和候选固定修订做决定，工具使用编写步骤的正文。已有资料时也可直接交给文件工具处理。没有正文步骤或引用资料时，可把已准备好的正文写入执行要求。选不出来时在原任务从同一候选中决定。普通 PowerPoint 排版与分页提纲使用各自的候选范围，工作簿制作与 CSV 汇总也分别配置。

新并行任务中的工具选择待办按步骤显示。完成其中一项后，该步骤从原候选继续，其他待办仍可单独处理。独立成果可以先预览，依赖该步骤的工作继续等待。暂停时先恢复任务，再核对当前待办。飞书可发「进度」查看哪些步骤需要选择，然后从链接回原对话操作。应用可从 `steps[].toolChoiceWaitScope` 区分 `step` 或 `run`，用 `humanActionUrl` 交给项目中获准的人员处理。

对于“这张收据比规程上限多了多少”，可直接将两份资料发给规划助手，也可以在文本 Agent 的检索选项里勾选「允许按原文金额求和或算差额」。运行时根据引文选择金额，交付中列出算式及每个金额的原文。网页项目默认勾选「缺少金额时等待我补件」。只有一项金额时，发起人可在原对话补一份原件，点「查看金额原句」从原件中选择一处。相同文字会分别显示字符位置，Word 还显示段落。查看和翻页不产生模型调用。Agent 从当前步骤继续，复用第一次检索，交付保留两处引用。逐行核对整张流水并生成 Excel 仍使用分组汇总工具。

当模型已选出金额编号、平台正在核对原文并计算时，桌面对话显示「正在按已核对的原文金额计算」。执行进程接管后可以从已保存的选择继续。计算结果保存为带公式及引文的候选，交付前仍由审核人核对。

包含并行分支的新协作任务里，原文问答和金额核算可以各自显示一个带步骤编号的补件表单。请在缺材料的步骤选择原件和引用，其他就绪步骤可以继续。依赖本步骤的后续工作仍需等待它完成。不同步骤可从同一份原件中分别选择各自的引文。补件后仍缺依据时，请按该步骤的新待办再次核对。

金额核算服务的网页入口在启动前提供等待补件选项。通过 Open API 启动时可设置 `awaitCalculationReceipt: true`。进度返回 `nextAction: "submit_receipt"` 时，用原应用或原成员委托向 `actionsUrl` 提交同名动作、当前控制修订 `expected`、待补步骤 `step` 和附件（文件名 `name`、Base64 正文 `data`）。多段文字还要提供原句 `excerpt`。相同原句出现多次时，另传 `excerptStart` 指定该句起始字符（从 1 起按 Unicode 码点计数）。相同补件重发时沿用同一幂等键。继续查询原运行，人工审核后下载交付包。[Open API 契约](../backend/internal/services/openapi.json)

进度中的 `receiptRequests` 列出可操作的原件补件待办。待办有 `receiptRevision` 时，补件动作须回传该修订。已有的 `receiptRequest` 仍提供第一条。飞书单聊可从原任务发「进度」，再按待办发「补件 #步骤编号 原句」，上传资料并核对当次确认指令。

## 本地运行

需要 Docker Compose、Go 1.27 和 Node.js 22。项目内已有工具链时 Make 会优先采用。执行 `make infra` 创建开发配置、独立数据库和 Temporal 服务。在三个终端分别运行 `make api`、`make worker`、`make web`。首次安装前端依赖使用 `npm ci --prefix frontend`。打开 http://127.0.0.1:15173 。在空实例中使用本机 `.env.local` 内的 BOOTSTRAP_TOKEN 创建第一位管理员。后续成员通过管理员签发的限时邀请注册。使用计算或 Office 成果工具时，先执行 `python3 -m venv .tools/connectors-venv` 和 `.tools/connectors-venv/bin/pip install -r connectors/requirements.txt`，然后在单独终端运行 `make tools`。本机运行 `make preview` 使用同一 Python 环境。Office 预览需要 LibreOffice 的 `soffice`，PDF 正文读取需要 Poppler 的 `pdftotext`。本机工具可通过 PATH 或项目的 `.tools/bin` 提供。容器部署自带独立预览服务。

首位管理员建号后会进入「团队首次配置」，之后可从「我的工作区 → 企业管理」返回。只有一个团队时直接显示费用承担方。加入多个团队时可切换配置对象。接入该团队获准使用的文本模型。百炼用户应从业务空间复制与密钥地域匹配的兼容接口根地址和已开通的模型 ID。[百炼官方配置说明](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)

管理员可以先授权一次模型连通验证，再指定新项目的默认规划模型。团队成员从「Agent → 内置 Agent 模板」打开简报整理、简报核对与 Word 成稿助手。前两项绑定文本模型修订，Word 使用部署的文档连接器。在每项的「必要检查」中查看样例并授权试运行，验证通过后可申请发布。可用的发布版本可直接带回当前对话。

管理员在「模型资源 → 维护模型与凭据」按模型修订查看受影响的助手、服务及本人有权查看的在途项目。同计费账号、地域和授权范围的密钥可单独轮换。填写原因并授权一次验证后，管理员明确启用新凭据。更换供应商或模型会创建新修订，原项目保持原绑定。

在同一页面展开「按批次替换助手的模型」，选择同团队、同操作的目标修订。页面列出服务与在途项目影响、原目标配置及单次估价。勾选助手并确认目标团队凭据后创建草稿。展开批次中的助手，即可对照两版样例和结果、复验并单独发布。需要回退时，填写依据并恢复原发布修订。每次切换只影响之后按当前发布修订拟定的方案。

三项就绪后，创建培训简报样例。样例包含合成资料、固定的助手修订和待确认方案。若要验证默认规划助手，在项目中请它规划并采纳其建议。确认费用后执行，核对成果、处理修改并确认具体版本，随后可下载 Word 交付包。团队配置页分别展示协作交付和默认规划建议被采纳后的交付结果。更换团队默认模型只影响新建项目。

管理员在「我的工作区 → 企业管理」选择文本对话或文生图操作，配置对应的 HTTPS 模型端点，填写服务根地址、模型 ID 和凭据。团队成员可描述 Agent、选择模型修订或绑定专用凭据。以有预期输出的真实输入试运行后，由管理员发布指定修订。在新对话中创建任务、配置协作顺序、确认方案和本次调用范围。成果按版本审核并由最终确认人确认交付。

文生图资源选择「文生图 · 单张 PNG」，填写支持同步 `images/generations` 和 `b64_json` 的兼容接口根地址。百炼可使用在本业务空间已开通的 `qwen-image-3.0` 或 `qwen-image-3.0-pro`。一次连通检查实际生成一张图，使用团队额度。给 Agent 配置必要检查，例如样例“生成一张圆形构图的概念图”，预期片段“PNG 图像”，再指定业务验收人。验收人查看原件、核对构图并提交结论后，管理员可发布。项目可按 PNG 匹配能力、原生预览、用文字反馈重新生成整张图，或上传外部精修的 PNG。交付包固定审核通过的版本。[百炼图像接口与模型支持范围](https://help.aliyun.com/en/model-studio/qwen-image-generation-and-editing-api-reference)

读图资源选择「视觉理解」，填写企业已开通且支持 `chat/completions` 视觉输入的模型端点。连接检查发送一张合成图。用户可在 Agent 入口创建「从图片提取或核对信息」的草稿，用图片和预期文字试运行，再按权限发布。业务对话可附 1 至 4 张 PNG 或 JPEG，单张最多 3 MiB，合计最多 6 MiB。执行前可核对所选图片版本和费用，视觉模型输出文本供审核。[百炼视觉输入示例](https://www.alibabacloud.com/help/en/model-studio/vision)

使用「参考图编辑 · 单张 PNG」资源时，模型端点须支持同步图片输入和 `b64_json` 输出。Agent 试运行和已发布服务各需一张 PNG 或 JPEG 原件。成果审核中，采纳修改要求后可交给原 Agent 编辑当前成果。勾选「仅修改选区」，在图上拖出矩形或输入像素坐标。平台保留选区外的原稿像素；出图尺寸不符时保留原稿并提示核对调用。修订版须重新审核后交付。对尺寸不符或需要专业精修的成果，可上传外部修订稿。[百炼兼容图片接口](https://www.alibabacloud.com/help/en/model-studio/qwen-image-generation-and-editing-api-reference)

成员在「我的工作区 → 个人偏好」可保存临时截止时间、确认复查或明确续期。默认 90 天复查、365 天有效；到期或删除的条目进入 30 天回收区。编辑正文保留期限，并使固定旧版本的方案需要重新确认。企业管理中的「允许登录」可临时停用账号。「办理正式离职」会注销会话、收回团队与项目成员资格并隔离偏好。重新入职后，成员可在原有效期和回收期内逐项验证密码恢复。Worker 启动时和运行期间每小时清理工作库中已过回收期的正文。

企业运维可以加密备份业务库、Temporal 执行历史与列表、以及平台对象文件。隔离还原会核对三库恢复点；正式库可用时，运维还可以按当前分发权限修复缺失的已交付原件。部署、轮换和演练步骤见[企业备份与恢复](17-enterprise-recovery.md)。

### 在对话中制作可编辑课件

在新对话输入需求，例如“用设备借用制度做三页培训课件”，打开输入框旁的 Agent 入口。已有已发布的课件 Agent 时可直接选用。选择「编写分页提纲」可自己填写各页。选择「让 Agent 编稿」可指定同一团队内已发布的文本 Agent，再附上制度文件。确认方案会列出编稿、排版的顺序和本次调用范围。

缺少课件能力时，在同一入口点「创建 Agent」，选择「可编辑课件（PowerPoint）」。排版使用内置连接器；需要新编稿能力时可点「从资料编稿助手开始」，选用企业已配置的文本模型。草稿可用样例试做、查看实际文件，验证后按权限发布。审核阶段可以指定某一页的标题、正文进行修改，旧版可继续对照。改过母版或图形的外部课件请用外部编辑并回传新版本。[已审核的三页课件](evidence/rebuild-course-deck/course-v2.pptx)

### 核对 Agent 是否保留了原文要求

在文本稿、平台制作的 Word 文档或分页课件下面展开「与方案原文对照」。选择方案引用的资料，勾选「只看未逐字出现的原句」。每条结果显示资料版本和原文位置。课件会标出出现在哪几页，或根据相同用词提示可能相关的页。改写也可能被列出，审核人可结合上下文判断。稿件中额外添加的说法需另行核实。

需要改稿时选定目标页，点「起草核对意见」，补充要求并提交。负责修改的人可展开「查看反馈引用的原句」。修改课件时，选中正文里的旧句再点「从反馈引用插入原句」，可把原句放回正确位置；没有选中文字时原句加入页末。提交改稿前仍能调整，执行后按新版本审核。[手机上的原句核对](evidence/rebuild-source-comparison/source-comparison-mobile.png)

### 从项目资料查找依据

打开项目中的「项目资料 → 在资料中查找依据」，输入问题或关键词。每个候选给出可核对的原句、文件名、版本和正文字符位置。项目发起人可把整份指定版本加入方案草稿。保存方案后仍需确认执行。资料换版后，新检索使用新版，已确认方案按原版本执行；资料撤权后，旧版原件访问也会受限。

默认使用 PostgreSQL 原词和词句检索。需要按意思检索时，可启用企业实例内的中文向量服务。当前适配固定的 BGE 中文小模型 ONNX int8 修订，模型与分词器在进程启动时校验摘要。准备该修订的 `onnx/model_quantized.onnx` 和 `tokenizer.json`，放入同一目录并将前者命名为 `model.onnx`。容器部署时将 `RETRIEVAL_MODEL_DIR` 设为该目录绝对路径，在原 Compose 命令上追加 `-f deploy/retrieval.yaml`。API 和 Worker 通过内部网络调用向量服务。[固定修订与模型文件](https://huggingface.co/Xenova/bge-small-zh-v1.5/tree/75c43b069aac4d136ba6bc1122f995fedcfd2781)

本机运行可用 Python 3.12 创建 `.tools/retrieval-venv`，安装 `retrieval/requirements.txt`。在本机配置中填写 `RETRIEVAL_MODEL_DIR` 和 `RETRIEVAL_URL=http://127.0.0.1:18728`，运行 `make retrieval` 并重启 API 与 Worker。Worker 分批补齐当前可读版本的向量，检索结果显示已索引段数。语义服务离线时仍可按原文查找，服务恢复后继续补齐。可检索 UTF-8 TXT、Markdown、CSV 和 JSON，以及 DOCX 的正文段落与表格、PPTX 可见幻灯片的文字、XLSX 可见单元格已保存的值、PDF 的文字层。检索结果显示所在段落、幻灯片、单元格或页码，可下载同版原件核对。原件限 8 MiB，提取正文限 256 KiB、4000 个位置，送入一次运行的资料合计约 96 KiB。扫描件需要另附文字，含嵌入对象、宏或外链的 Office 包仅保留原件。表格复杂格式及公式请在原表核对。

### 用多份 CSV 生成可复核的报表

在对话中选择分组汇总 Agent，一次附上多份 CSV。确认方案时展开「汇总输入」，核对文件及版本。下载的 Excel 有「汇总」「来源核对」「计算口径」三个工作表。来源表逐份列出读取、纳入、排除行数与纳入金额；没有匹配行的文件也会出现。不同资料按行合并，同名文件以资料标识和版本区分。原始业务记录如有重复，须按业务口径另行处理。

工具按表头映射列，每份最多 10000 行，单次最多 20 份，项目运行仍受资料上下文容量限制。金额最多两位小数，允许负数。可配置单位列，常见币种表头（如 currency、币种）可自动识别。纳入记录的单位冲突或部分缺失时，需要修正资料。全部输入都没有单位列时，结果明确标注单位待核对。超过 Excel 安全数值精度的金额保留为精确文本。含非 CSV 输入、缺列或金额格式错误时，汇总停止并给出原因。如果所需数据在原表中采用了其他列名，项目发起人可展开「核对汇总字段」，下载指定版本的原件，选择字段对应并授权一次新计算。平台保留原运行编号、已完成步骤及每次调用记录。工作簿会多一张「字段对应」表。原表确实缺少数据时，可核对回执并结束运行，使用补齐后的资料重新发起。

### 网页服务对话

在「我的工作区 → 服务与渠道」中发布单个助手或已确认的协作方案，可为每个版本填写用途和使用示例。选择服务后点击「打开独立服务对话」，即可将地址分享给已获团队授权的成员。业务人员也可以从新任务中展开「可复用的团队服务」，按需求里的业务词查看匹配原因。进入服务页后，可自行选择带入原对话的首条需求。

成员登录后能查看服务版本、步骤、审核人和费用承担团队，可在本次请求中附一份 UTF-8 的 TXT、Markdown、CSV 或 JSON 资料（最多 96 KiB）。确认调用后进入项目，资料固定到本次方案。回到服务入口能继续自己最近的任务，交付包由最终确认人核对成果版本后开放。发布新版会更新同一链接，新任务须重新核对新版的调用范围；已受理项目仍保留原服务版本。

管理员在「我的工作区 → 服务与渠道」选择服务后，可展开「版本与回退」。对照历史版本的资料要求、步骤、能力修订和最终确认人，核对预检结果并填写回退原因。网页和飞书的新任务随后确认目标版本，已受理任务继续按原版本办理。应用通过 Open API 读取当前默认版本，并在调用中明确指定所需版本。

### 业务系统调用已发布服务

在「我的工作区 → 服务与渠道」选择服务，打开「Open API 与身份委托」。团队管理员签发限定该服务的 Bearer 凭证，普通成员可选择一个获授权应用，签发自己的短期委托。成员和管理员分别可以在原处撤销委托和应用。服务端通过 `/api/v1/openapi.json` 提供可导入的接口契约。[OpenAPI 文件](../backend/internal/services/openapi.json)

1. 用 `GET /api/v1/services/{id}` 核对版本、步骤、调用次数和最终确认人。涉及成员身份的每次请求还须带受理时使用的 `X-Alliance-Delegation`。
2. 向 `POST /api/v1/services/{id}/runs` 提交 `version`、`input` 和 `authorizeCalls`，并保存本次请求的 `Idempotency-Key`。202 响应包含运行、项目和状态地址。
3. 查询状态地址查看步骤、成果版本、阻塞原因及下一项人工操作。调用 `actionsUrl` 可暂停、恢复、取消，给尚未提交的文本步骤补充信息，或针对当前成果版本提出修改建议。控制与补充使用当前 `controlRevision`，每次不同操作使用新的幂等键；同一请求失去回执时沿用原键。
4. 访问 `eventsUrl` 可按 `after` 游标分批读取事件，每批最多 100 条。使用 `Accept: text/event-stream` 可在已认证连接上接收同一批业务事件，连接最长 25 秒。客户端处理后保存最后一个事件 ID，重连时带 `Last-Event-ID`。代理需转发 Authorization、委托凭证和游标，并允许流式响应。
5. 将 `humanActionUrl` 交给获授权的成员，使用其平台身份审核。待 `nextAction` 为 `download` 时，原调用身份访问 `deliveryUrl` 或 `packageUrl`。撤销应用或委托后，请求和事件续传都会重新核验权限。

服务描述的 `requiresPictures` 为 `true` 时，通过 `attachment` 传单张图片，或通过 `attachments` 依次传多张。每项提供原文件名 `name` 和原字节的 Base64 `data`。网页使用同一规则。飞书给出网页入口，登录后附图并确认。

最终确认人在「最终交付清单」逐项核对版本与包内依赖，可填写给接收人的用途、使用说明和已接受的限制。确认后，项目成员能在原对话展开已确认清单，外部调用方也能从 `deliveryUrl` 和 ZIP 的 `manifest.json` 读取同一份说明及依赖版本。已有交付的说明保留为空。最终确认时平台先生成 ZIP，并核对文件摘要。若原件缺失或受损，项目留在审核阶段，管理员恢复原件后可沿用已审核版本重试。

交付后，有本项目审核权限的成员可从最新批次的「发起交付后修订」选择成果和原因。平台把意见登记为必须处理的修改，原包继续可下载。改稿后由反馈负责人复核，再由最终确认人确认新批次。可在批次选择器核对正文或摘要变化、文件替换、上游引用换版、沿用项数和交付说明变化，展开单项对照两个版本，并分别下载原件。Open API 的运行进度列出已确认批次及各自的下载地址；未带 `edition` 的历史下载链接固定指向第一批。

在「项目资料 → 资料版本与引用影响」中，可以核对版本和引用，再提交新版或撤销原件访问。审核页按成果分别处理资料变化；交付清单保留当时的依据版本及核对回执。

交付确认后再撤销引用资料，平台暂停涉及批次的清单正文与 ZIP 分发。项目对话顶部及「我的待办 → 成果审核」显示受影响成果；资料负责人或项目发起人按版本选择「仅原资料无法访问」「结论需修订」或「包含受限内容」，填写依据。所有相关项均核准独立分发后，原包才重新开放。修订某项可另行确认新批次，旧版本继续按自己的决定处理。通过 Open API 查询运行进度的 `deliveries[].distribution` 可识别每一批的状态，成功下载响应的 `X-Delivery-Distribution` 标明本次发送时的状态。

进入审核阶段后，打开「项目反馈」可把一段对话意见分配到多份成果。确认每一项的目标版本、处理方式和负责 Agent，有歧义的意见可暂缓。之后可在目标成果的「反馈」中查看原文、发起改稿并复核。

在对话的「项目协作 → 转交最终确认权」选择已有项目访问权的成员。接任人从「我的工作区 → 确认权交接待办」查看影响并接受或谢绝。接受之前仍由原确认人负责。原确认人已停用或失去项目审核资格时，具备本项目访问权的本团队管理员可在「项目协作 → 异常接管最终确认职责」提名接任人，写明影响及结束条件。接任人需逐项审核当前版本后才能确认交付。固定交付包保留原审核人、最终确认人及适用的接管复核记录。

项目已无在职参与者且负责人已离职时，本团队管理员可在「我的工作区 → 无人负责项目恢复」按项目编号提名在职成员，说明原因并指定授权期限。候选人在「项目临时接管」接受后获得限时访问权，逐项复核当前版本后可以确认并下载交付包。交付、到期、撤权或离开团队都会结束临时访问。

从左上角打开对话历史。可按标题或状态搜索，切换到「我的待办 → 成果审核」可查自己能审核的当前版本、分配给自己的反馈以及需要自己最终确认的交付。点选待办会重新读取项目并定位到对应成果。切换对话或使用浏览器前进、后退时，消息、待附文件、未提交的成果意见、人工改稿及协作方案草稿在当前页面内暂存，刷新或退出页面后清除。方案草稿保留步骤依赖、资料与偏好版本。如果项目修订变化，核对当前内容后可以继续使用草稿或放弃修改。执行前会展示各步成果的修改方式和最终确认人。每份成果可单独暂存正在修订的正文、原因或外部 Office 文件。成果换版后先核对最新正文或下载原件；文件修订需再选择准备提交的文件。

项目资料换版后，在受影响成果中打开「资料依据核对」。若判断需要改稿，记录原因，在生成的反馈下展开「交给 Agent 修改」。可单独勾选本次改稿采用的新版资料，然后授权一次调用。成果版本记录和交付包清单均可核对这次选择。

预算负责人可从左上角对话历史打开「我的待办 → 预算追加」，搜索自己负责的各团队申请，核对最新额度后批准或拒绝，并查看回执。承担预算的职责只开放财务申请资料；项目标题和进入项目的按钮按项目成员权限显示。

`make build` 编译 Go 服务并构建前端。单机镜像配置可通过 `docker compose --env-file .env.local -f deploy/compose.yaml -f deploy/application.yaml up -d --build` 启动，浏览器入口为本机 18485。正式部署应使用 HTTPS 反向代理、开启安全会话 Cookie，单独保管配置、加密密钥与数据库备份。本地开发端口和凭据均与旧实例分离。 使用 Docker BuildKit 构建时，npm 与 Go 下载缓存可跨构建复用。首次构建需能访问锁定依赖及基础镜像的来源。

在「我的工作区 → 团队规则」选择已加入的团队，成员可起草或修订，团队内的管理员可发布和停用。打开「维护者与交接」可提名接任人，待本人接受后生效。维护人离开团队后，本团队管理员可补任。「我的规则维护待办」显示跨团队的待接受、缺位与复查事项。引用项目及其固定版本可在「项目引用与交接记录」中查看。维护人复查长期或临时规则后，下次复查日期顺延 90 天，临时规则的截止时间保持原值。「协作方案 → 方案采用的团队规则」可查看本次固定的版本。

规则默认适用团队全部步骤。起草时可选择适用的 Agent，由管理员核对正文和范围后发布。限定规则失效时，相关步骤会在原任务列出规则待办，独立步骤可以继续。发起人可在该步骤首次调用前核对可用版本并确认接续。飞书「进度」和任务卡会提示待核对步骤，链接到原任务。Open API 可从 `ruleWaits` 读取首次派发前的待办，用 `recheck_step_rule` 提交 `step`、`waitRevision`、`ruleRevision` 和当前控制修订 `expected`。

已经使用失效规则或受影响结果时，在原任务打开「核对重做范围」。检查要重做的步骤、可沿用的成果版本、尚未开始的步骤、当前可用规则及本批调用上限，再确认关联批次。如果已有调用仍在途或结果未知，按原号查清回执后再确认。确认后，已完成的合法成果保留原版本和原费用；有影响的新候选重新审核。Open API 在 `nextAction` 提示 `preview_rule_branch` 时从 `ruleRebuildUrl` 读取清单，提交 `rebuild_rule_branch`、`rebuildDigest` 和 `authorizeCalls`。确认动作沿用同一 `Idempotency-Key` 可取回原回执，或从原运行的 `replacementRun` 继续查询已受理批次。

## 外部 Agent

在 API 与 Worker 的 `AGENT_ALLOWED_HOSTS` 中配置企业准许的 HTTPS 主机，多个主机以逗号分隔，非默认端口要一并填写。能力库支持粘贴 A2A 0.3.0 JSON-RPC Card，或从公开地址读取。提供服务根地址时会读取 `/.well-known/agent-card.json`。核对描述并保存草稿后，通过实际试运行取得验证证据再发布。有多个接口的 Card 可从公开声明中选择 JSONRPC 调用地址，每个修订固定一个地址。相同地址可沿用该 Agent 的专用凭据，变更时须重新配置。

外部调用返回任务编号后，Worker 使用 `tasks/get` 跟进原任务。提交超时、单次查询时限、整轮核对窗口、查询间隔及读取失败重试次数按 Agent 修订保存。默认读取失败最多重试两次，可降为零。缺输入、缺授权或核对窗口到期会在项目中显示处理入口。取消会登记远端停止请求，平台以远端回执显示实际结果。无有效编号的未知提交仍由负责人核对。试运行的原回执可在能力库中查询或申请取消。网页为每次试运行生成请求键，响应丢失时再次提交相同内容可找回原记录。直接调用验证接口的客户端应在首次请求提供 `Idempotency-Key` 并在重试时沿用，输入或修订有变化时使用新键。[A2A 0.3.0 规范](https://a2a-protocol.org/v0.3.0/specification/)

对于没有远端编号的未知调用，项目负责人可展开「调用记录 → 调用核对」，在一次局部改稿中也可由仍具审核权限的原发起人处理。记录核对依据后可以继续等待；若原请求已经返回且结果未知，可单独勾选重复执行和费用风险，授权同一步骤再调用一次。平台重新检查资源、资料和预算，保留原调用和原账目。已取得远端编号时继续查询原任务。

适用的文本步骤显示「正在核对模型回复」时，原回包和用量已入账，候选尚待复核。暂停后可从原回包继续，恢复时会重新检查输入与授权。回复截断的工具选择交由经办人处理。普通文本回复未完整结束时，该步骤没有可审核的候选，发起人可以取消后重新发起。

原文问答、证据复核和金额核算也会显示这一核对状态。平台按模型当时看到的引文与金额编号继续补查或核算。如果资料、位置或可读范围已经变化，调用记录会提示核对依据，相关候选在重新确认前无法提交。

若 Worker 在发出请求后失联，在「调用核对」中可查看执行截止时间与原回执核对截止时间。模型和内置工具分别按 90 秒和 45 秒执行时限，再留出 15 分钟核对；外部 Agent 使用已固定修订中的时限。核对窗口内可登记依据并继续等待。时限结束后由有权限的成员决定是否承担风险重新执行。原回执先到时沿用原调用；确定重新执行之后到达的回执单独保留，可核对批次、到达时间、结果指纹及供应商返回的用量。


## 选择和复用 Agent

要让方案按任务内容选用文本 Agent，在后续文本步骤指定一个已发布的备选，并关联一个可独立运行的前置文本选择步骤。两项候选必须属于项目团队。第三方候选须有已验证的文本操作。保存后，执行方案会显示两个固定修订、费用估算及可能发送给第三方的输入范围。

选择步骤负责选定其中一个修订。执行步骤以原任务、已选资料、适用记忆和明确引用的其他前置成果继续。模型弃权时，经办人可在原任务选择其中一个。飞书进度可以打开对应待办。项目记录实际执行者和费用。若已选修订随后失效，需核对其授权或能力状态。

在项目的「拟定协作方案 → 比较候选能力与验证依据」中选择这一步需要的成果格式，输入任务名称或验收项关键词。每条候选展示可见团队的具体修订、已通过的验收项、复查日、单次估价和有效试运行的耗时中位数。相同匹配与复查条件下可优先看低费用或较短耗时。把候选加入步骤后，仍需保存并确认整套方案。规划助手会从当前可用修订中提出建议，打开「核对推荐版本与替代能力」可核对当前证据。规划答复返回前会再次检查权限、修订和额度；条件已变化的答复标记为已过时。用户重新核对并授权后可以再发起一次规划，结果未知的原调用可刷新查看。

新建模型 Agent、启用工具或注册外部 Card 时，相似能力提示会说明对应名称、任务说明、工具操作或调用地址。能力库内可定位已有条目，模型草稿可显式套用发布版的任务说明，模型及凭据另行配置。在项目缺口中可直接选择已有发布版本，随后确认绑定。

在相似条目内选择「向维护者提出增强需求」，明确针对的版本、业务改动和验收要求。提交后可在「团队能力库 → 能力增强需求」查看记录。当前维护者受理后，通过常规草稿、验证和发布流程完成新修订，再关联发布版本、填写核对依据。计划和服务继续使用各自固定的修订。

每个 Agent 的「维护者与交接」可提名同一团队的有效成员。接任人明确接受后承担该能力的需求处理与证据维护。原维护者离队时，团队内管理员可提名接任者。离队会取消涉及该成员的待接受交接，重新入队后需重新授予维护职责。

## Agent 验收清单

在「团队能力库 → 必要检查」为当前修订编辑验收要求、团队共享样例和预期输出。文本可按完全相同或包含片段判断。填写业务验收人邮箱后，该成员可以查看实际试运行结果、预览或下载生成文件，并提交带依据的结论。每次试运行都需单独授权，一次调用只记一条费用记录。

维护者可以在团队 Skill 包的 `manifest.json` 用 `"activationTerms": ["核对报价", "比价"]` 声明任务触发词。每项为 1–80 字的连续文本，最多 8 项，英文字母忽略大小写。任一词出现在任务正文中，或成员在同一输入中用 `@skill-name` 点名时，平台读取 Agent 已绑定的对应修订及其固定依赖。常规任务可在需求中点名，已发布服务以成员或应用提交的输入为准。附件内容、服务的默认说明和前置步骤正文仅作为执行资料。省略触发词时，绑定的包照常加载。

发布前，为每个配置触发词的直接绑定 Skill 准备并通过至少一条实际命中的样例。在构建核对中查看每个 Skill 的样例覆盖，在项目「调用记录」中查看本次使用的 Skill 修订。新版 Skill 需重新绑定才能进入新版 Agent；停用旧版时，相关运行和候选会按实际引用复核。

团队管理员可从「发布历史与恢复」查看当前和历史修订的清单，核对模型、Skill 和验收证据后填写恢复原因。确认后，能力库和之后拟定的方案使用恢复的发布修订，已确认项目仍使用各自保存的版本。发生过模型批次替换时，属于该批次的原修订从批次页面恢复。

在已交付对话中保存新协作模板时，平台登记各步骤和备选工具的构建清单。模板详情标出待复核的步骤。发布模板前需更新失效或换版的能力。使用已有模板开展新任务时，可以在方案中逐步替换不可用的能力，再核对本次资料和费用。

保存模板时，逐项编辑并确认可复用的必交项。新项目预填这些条件，缺项时默认等待补齐。模板标记为支持部分交付时，也需由本次项目发起人明确勾选。采用新版模板时，核对原方案和新版的必交项。删除或更换对应步骤时需确认，原方案保留原有记录。

首次试运行冻结清单。配置多项检查时，发布需要每项均通过。尚未配置清单的修订沿用单次试运行规则。新修订继承清单，重新取得证据。可在「试运行记录与回执」说明原因并标记证据失效；项目保留历史成果和原修订，新的服务请求会检查当前可用性。运行中遇到证据失效时可在项目内展开绑定修订的必要检查，复验后恢复。复查日期按必要证据中最早到期的一项展示，默认 90 天。

方案缺少 PNG 制作能力时，可直接在当前对话创建生图 Agent。填写样图要求和验收标准，项目所属团队只有一个已启用且凭据、预算均无阻塞的生图模型时，会预选该修订并显示费用承担方。默认由创建者看图，也可以指定模型所属团队的其他成员。样图验证和共享发布通过后，原方案可直接使用该修订，与 Word 等其他成果一起审核交付。

## 团队与项目预算

管理员在「企业管理 → 预算管理」选择团队，指定预算负责人并填写原因。已有实例升级后也需要完成这次委任。预算负责人可以是普通成员，在「我的工作区 → 预算管理」调整额度与提醒线、登记账单。移出团队会撤销这项授权。未参加项目的预算负责人可以查看项目编号、财务信息，以及申请人明确提交给审批的说明。

成员发起新对话时沿用有效默认团队或唯一可用团队。需要更改归属时可展开「项目选项」。在能力库登记内置工具或外部 Agent Card 时，单独选择资源归属及费用承担团队。成员属于多个团队且未加入企业默认团队时，首次发送普通任务需明确选择。该任务创建成功后，同一页面的下一次新对话会在「项目选项」显示并沿用所选团队，成员可以更改。刷新页面后重新判断。如果在填写期间退出所选团队，保留草稿，重新选择后才能提交。修订已登记的能力会沿用原团队。

借用其他团队的能力时，先邀请该团队成员加入项目。成员在对话中展开「跨团队能力授权」，选择修订并填写用途、天数和次数。提供方的资源管理员与预算负责人可在「我的工作区」分别确认，项目发起人随后可将该修订加入协作方案。方案会提示剩余调用次数不足，实际调用计入提供方团队账本。项目可核对并重新申请此前已获准且仍有效的旧修订。

方案确认前会显示已有估价的调用次数与合计金额、价格未知的调用次数，以及当前项目或承担团队的额度不足提示。执行每一步时按实时账本核验。项目参与者从对话内的「项目费用」查看额度、预占、已记账金额和待核对笔数。有预算权限的成员可在此追加额度。规划、执行、改稿及项目内发起的指定修订试运行都要通过项目额度与资源承担团队额度的检查。团队能力库内独立发起的试运行计入团队费用。预算不足时可以调整方案，或由负责人追加额度后恢复。未知费用仍需单独授权，供应商实际结算可能超过预估，账单按实际金额登记。

项目参与者可从「项目费用 → 预算追加申请」选择项目额度或相关承担团队额度，提交追加金额、剩余工作及替代方案。申请保留提交时的已用金额和待核对用量。若涉及已阻塞运行，可在提交时选中原任务。负责人在「预算管理 → 预算审批与记录」核对当前额度及批准后的金额，写明批准或拒绝依据。申请人可撤回待审申请。审批结论和时间回到原项目，具备运行控制权的成员可在获批记录中选择「复查并继续原任务」。恢复时继续检查权限、预算和运行状态。项目已交付、采纳或取消时，仍待处理的申请随项目关闭，历史申请保留结论和原因。

预算负责人在「预算管理 → 资源额度」可以为每个注册模型、工具或外部 Agent 设置金额和累计调用次数。多个 Agent 使用同一个注册模型时共享这两项额度。修改该资源的修订保留历史用量。试运行、规划、执行及改稿均在派发前检查适用的资源、项目和团队额度。已受理调用占用一次次数，查询原回执及同键重放沿用既有记录。已知零费用操作仍受调用次数限制。

资源阻塞时，在项目的预算追加申请中可选择具体资源，分别申请金额或整数次数。审批记录显示对应单位。团队财务明细记录调用时的资源名称与修订。已停用资源的历史用量保留。

涉及数据库 036 的升级应在同一维护窗口更新 API 和 Worker。迁移按旧规划请求、试运行或固定执行步骤关联历史账目。无法确定来源的旧记录可继续核账，并显示「历史资源未关联」。

升级涉及数据库 054 至 057 时，在维护窗口停用旧工作进程，再用同一发行版本启动 API 和 Worker，恢复服务后开放单步改稿。旧 Worker 无法隔离重新授权后才到达的原回执；所有旧 Worker 停止后，再开放风险重做。恢复派发前应确认进程已经切换。

## 企业管理大盘

管理员从「我的工作区 → 企业管理 → 运行监控」按发起成员或应用查看近 7、30 或 90 天的活动。执行完成显示所选期间发起且目前已完成的运行数。能力样例检查按检查完成时间计数。成果审核按版本计数，简单回答按明确采纳计数，正式交付按确认批次计数。这三项分别按事件发生时间归到项目发起人。应用自主发起和应用受成员委托发起分别归到应用和该成员。

默认展示全体汇总。选择具体成员或应用后，数量与金额同时收窄到该发起人。费用归集所选期间发起的调用。已记账金额包括已入账的部分账单，剩余预估只计算未结算调用尚未覆盖的预估金额。金额未知的未结算调用单列笔数。汇总界面仅展示计数和金额，项目正文和逐笔账单继续使用各自的授权入口。

「运行状态分布」列出执行中与执行失败数量，展开可看待派发、执行阻塞、待核对回执、暂停、完成和取消。每次运行按发起时间归入周期，只占一个当前状态。运行结束后再查询同一日期，其状态会更新。已生成的汇总下载保留生成时的分布。项目团队承担运行归属，费用仍按资源承担团队统计。

外部 Agent 明确返回失败或拒绝时，项目发起人可以在「控制运行」填写原因并确认执行失败。单步改稿也可由仍有审核权的改稿发起人在「管理本次修改」处理。所有已派发调用（含风险重做前的调用）须有可核验的终态回执。确认结束后，保留已有成果和调用费用，当前改稿的候选分支结束。应用从进度接口读取 `canConcludeFailure`，向运行的 `actions` 提交 `confirm_failure`、当前控制版本和原因。升级数据库 072 时，在同一维护窗口更新 API 和 Worker，使执行进程识别失败终态。

### 回收、恢复和清除项目资料

从「项目资料 → 资料版本与引用影响」查看本次操作涉及的版本、方案、运行、候选成果与历史交付。资料创建人和项目发起人须仍是该项目成员，才可提交处理原因并确认操作。

| 操作 | 成员看到的变化 |
| --- | --- |
| 撤销访问 | 原件、预览、文本差异和检索入口关闭，平台保留资料内容供后续处理。 |
| 移入回收区 | 全部版本停止普通访问和后续调用，30 天后进入清除。曾经允许分发的关联成果回到待核对，已记录的分发决定可追溯。 |
| 恢复为新资料 | 在回收期内按当前权限操作，在原项目生成新的资料编号，保留各版原件、作者和时间。原先已撤权的资料仍受限。使用新资料须重新选择并确认；旧链接、任务和交付继续按原记录处理。 |
| 彻底清除原资料 | 在回收区再次确认后，工作库解除原件引用，清除各版本文件名、提取文本和向量，保留版本编号、时间和处理记录。Worker 启动及每小时清理无其他引用的文件。页面标识排队、待重试或完成，以及其他资料或正式成果继续引用的文件数。 |

备份依企业轮换策略另行处理，运维应检查归档与异地副本。已发给外部系统的文件需由接收方处理。采用数据库迁移 075 时，在同一维护窗口更新 API、Worker 和备份工具，避免旧程序绕过新的对象写入和清理协调。部署后须核对 Worker 对对象卷的写权限。

研发环境可运行 `python3 scripts/smoke_source_upgrade.py`，使用独立测试库验证旧版资料、已撤权资料和固定任务引用。恢复前会逐个核对原件大小与摘要，原件缺失或损坏时保留当前回收状态。

资料撤权后，项目成员仍可查看意见的状态、负责审核人和成果版本。反馈正文、定位引文、修改说明和核对依据按当前项目职责展示。重新批准某版成果分发，只开放该版交付内容。同一条意见分配给多份成果时，只有对所有目标均有相应权限的人可读这条意见。整份项目反馈原文也按全部目标核验。

### 接入企业单点登录

先初始化首位管理员。企业身份管理员在身份源创建机密 OIDC 客户端，启用授权码流程、PKCE S256 和 RS256 签名，将回调地址准确登记为 `<PUBLIC_BASE_URL>/api/oidc/callback`。在 API 部署环境配置企业 HTTPS 根地址 `PUBLIC_BASE_URL`、身份源签发地址 `OIDC_ISSUER`、`OIDC_CLIENT_ID` 和 `OIDC_CLIENT_SECRET`。企业私有 CA 可通过只读卷挂入 API 容器，将 `OIDC_CA_FILE` 指向容器内的 PEM 文件。客户端密钥由部署人员保存在企业的密钥管理系统中。

1. 设 `OIDC_MODE=optional` 并启动 API。已有成员用原账号登录，从「我的工作区 → 企业登录身份」核验平台密码，再到企业身份源验证并绑定。新成员从「我有企业邀请」进入，填写邀请资料和平台密码后选择「验证企业身份并加入」。邀请在身份验证、成员创建和绑定均成功后一次性核销。外部邮箱与本地邮箱相同也需要显式绑定。
2. 要求全员单点登录前，用一个已启用的管理员账号完成绑定并试登。设置 `OIDC_EMERGENCY_MEMBER_ID` 为预先指定的在职管理员成员 UUID，再设 `OIDC_MODE=required`。在维护窗口停止旧配置的全部 API 进程并以相同配置启动。切换会作废旧会话，成员需重新登录。管理操作仍按平台角色和原有的二次验证执行。
3. 身份源故障时，指定管理员从专用应急入口填写原因并验证平台密码，应急会话最长 30 分钟。恢复后重新用企业身份登录。正式切回可选模式需要显式配置。强制模式下仅删除环境变量会阻止 API 启动。
4. 绑定按签发者、客户端和稳定主体标识识别。平台停用成员即时阻止其访问，办理离职会清理绑定。身份源单独停用员工时，其已签发的平台会话最长持续至 ID token 到期或 12 小时，以较早者为准。需要立即阻断时在本平台一并停用。企业现场需核对其实际身份源的声明、会话期限和停用流程。

复验命令为 `make smoke-oidc`，使用独立的本地 Keycloak、测试数据库和浏览器。测试账号与证书在演练时生成。[OpenID Connect Core](https://openid.net/specs/openid-connect-core-1_0.html)

### 从成员资料核对用量和账号变更

在「企业管理 → 用户管理」按姓名、邮箱、当前团队、角色或账号状态查找成员。打开资料后可查看部门、注册方式和账号变更记录。「查看此成员用量」沿用大盘选定的周期与团队。运行和交付计入项目团队，费用计入实际承担团队。选择成员后可从大盘返回资料。应用身份单独统计。

管理员修改角色、登录状态或办理离职前，可查看变更前后状态、待最终确认的项目数、待审核的成果版本数和委托数。提交须填写原因并重新验证管理员密码。两位管理员同时编辑同一账号时，后提交者先核对最新资料。暂时停用会撤销登录和已有成员委托，恢复登录后可重新签发委托。业务确认权按项目单独交接。

角色或登录状态实际改变后，成员从「我的工作区 → 账号通知」查看变更时间、操作人、原因和前后状态并逐条标记已读。停用期间的通知可在获准恢复登录后查看。部署此功能之前的操作仍可在原有账号记录中追溯。

### 授予企业、团队或部门汇总查看权

管理员在「企业管理 → 管理汇总授权」选择成员，再明确选择企业全域、团队或部门，填写期限与原因。授权表单默认 30 天，可设置 1 至 365 天。可单独勾选该范围的用量和费用。成员随后从「我的工作区 → 获授权的管理汇总」选择范围和周期。每次只显示一个范围的合计。当前范围失效后需明确选择其他范围。跨团队任职和项目参与本身均不产生此授权。

企业全域汇总包括所有团队、部门、应用发起的活动及未记部门的历史事件。跨团队任务在企业内只统计一次。团队的运行、审核、采纳和交付归入项目所属团队，能力样例归入 Agent 所属团队，费用归入实际承担团队。部门按建项时的发起人和记账意图创建时的调用发起人归集。调岗保留历史归属。升级前缺少部门快照的数据仅在有依据的团队和企业口径下展示，应用自主调用也可没有部门。

管理员可在有效授权清单中撤销一项授权并写明原因。最近 50 条已结束授权可核对原授权人、原因和结束时间。成员离开相应团队或部门时，该范围的授权结束；停用账号会结束其全部汇总授权。重新加入或重新启用后需要明确授权。汇总不附带成员明细、项目正文、账单明细和导出权。每次请求核对授权，已打开的页面在刷新、重新可见或最长 30 秒的定期核对时更新。

### 按成员查看任务

管理员在「管理汇总授权」中为指定团队或部门选择「查看成员与任务明细」。需要分辨某项任务的费用时，选择包含逐任务费用的权限，并填写调整原因。成员打开授权范围及周期，展开「成员与任务明细」，可按发起人的名称筛选，也可以直接查看全部任务。每页 25 条。任务显示编号、状态、发起人、当前最终确认人、经过时间及阻塞类别。

费用按该范围实际承担的记录显示。其他团队承担整项任务费用时，页面显示「本范围没有该任务的费用记录」。逐任务费用权、汇总费用权及汇总导出权分别配置。收回明细权后仍保留获准的汇总，成员和任务查询立即失效。

### 导出已授权的管理汇总

管理员可在企业、团队或部门汇总授权上单独开放导出。拥有企业全域导出授权的管理员，在运行监控选择全部发起人后也可直接准备导出，沿用大盘实际查询的起止时间。选择单个成员或应用时，界面收起全域导出。成员先核对范围、起止时间和字段，再填写接收对象与使用目的。文件采用 JSON，默认仅含业务数量；同时拥有费用查看权时，可主动加入调用、token、已记账金额、剩余预估及待结算笔数。接收对象与用途记录在审计中，文件由发起成员自行下载。

生成时固定结果。成员可以在同一范围下重新打开最近十份有效文件，每次下载均使用当前登录身份核验原授权。下载最长有效一小时，原授权先到期时同步截止。关闭导出会使已生成文件立即失效，汇总页仍能使用；重新开放导出后可生成新文件。后台按小时清理过期临时文件内容，来源统计与审计记录分别保留。

## 运行诊断

从项目内的「运行诊断与 Trace」选择原运行或局部改稿，展开依赖、耗时与状态事件。发起人可按运行、成员和到期时间授权结构、正文节选及导出。团队诊断保留期默认为运行结束后30天。管理员可在企业管理中调整期限或指定团队负责人，每个已结束运行保留已确定的到期日。

企业使用自己的监控系统时，在 Worker 环境配置 `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`，填入可达的私有 OpenTelemetry Collector 完整接收地址，例如 `http://collector:4318/v1/traces`。工作区使用 PostgreSQL 记录实时进度。Worker 通过 OTLP/HTTP Protobuf 发送已结束的运行和调用，带稳定的 Trace ID、步骤关联和筛选后的状态事件，接收端恢复后可补发保留期内的记录。企业负责接收端的访问控制和留存期限。管理页的「Trace 采集状态」可查看本机队列和接收结果。

## 合成数据集成验证

对话中的团队选择另有独立浏览器 Mock。启动本地网页后，可执行 `SMOKE_ORIGIN=http://127.0.0.1:15173 VISUAL_EVIDENCE=.tools/conversation-team node frontend/tests/conversation-team.mjs`。三个视口分别验证唯一团队、多团队选择、草稿撤权与零成员关系，并输出报告及手机实屏。

执行 `make smoke` 构建当前服务并启动隔离走查。每批使用独立的前端依赖、浏览器测试程序、连接器环境和 Go 二进制文件，开发工作区可继续使用。需要 Docker Compose、Python 3、OpenSSL、Node.js、Go、可执行的 LibreOffice 和 Poppler 的 pdftotext，首次会安装 Chromium 和连接器依赖。走查使用本地模型及 A2A 替身，实际调用编排、数据库、文件、计算和浏览器，另用独立的 OpenTelemetry Collector 容器验证采集协议与接收端中断恢复。每次执行将运行条件、已通过检查和最终结果单独写入 `artifacts/rebuild-smoke/<批次>/result.json`，输出同时给出临时服务日志位置。

## 公开 Agent 集成验证

执行 `make smoke-public`，或通过 `PYTHON_A2A=/path/to/python3.12` 指定 Python 3.12。此走查需能连接 PyPI 和 GitHub。脚本从固定提交读取并校验公开样例的文件，只调整部署监听和服务通告地址，在本机以独立进程运行上游 A2A SDK 与原执行器。通过平台发现 Card、验证、发布、执行、审核并下载 ZIP，核对文本字节、版本及摘要。每批的 `public-agent.json` 单独记录实测范围、上游版本、试运行和业务运行编号。此样例的能力为固定问候文本，运行无需云模型。[公开 Hello World Agent](https://github.com/a2aproject/a2a-samples/tree/209d47d5fc4012c7008b8d1ff3a040691ec11c5a/samples/python/agents/helloworld)

## 实现追踪

当前功能覆盖及剩余工作见[重建对照清单](15-rebuild.md)。此前版本的验证报告对应当时的代码和资源，重建后的运行需要重新验证。

### 核对逐笔调用费用

在「企业管理 → 管理汇总授权」为成员选定企业、团队或部门，勾选费用汇总和「允许导出逐笔调用费用与入账记录」。已有费用授权可单独开放或关闭逐笔导出。成员从「获授权的管理汇总」下载 JSON，拥有全域财务授权的管理员也可在大盘的全部发起人视图导出。

文件按调用发生时间筛选，记录发起人、承担团队、调用时的部门、记账资源、已知 token 和本次调用的各笔入账。金额保留十进制精度，以生成文件时的平台账本为准。金额未知、缺少归属与待结算均有独立表示。每份文件最多一万次调用，可在表单缩短时间范围。文件在原授权期限内最长有效一小时。

### Slack 单聊入口

管理员在 Slack 安装企业应用，启用 App Home 的 Messages，开通 `im:history` 和 `chat:write`，订阅 bot event `message.im`。为 API 配置 `PUBLIC_BASE_URL`、`SLACK_APP_ID`、`SLACK_TEAM_ID`、`SLACK_SIGNING_SECRET` 和 `SLACK_BOT_TOKEN`。Events API 使用企业 HTTPS 地址下的 `/api/channels/slack/events`。一个实例连接一个配置的 Slack 工作区及应用。[Slack HTTP 事件设置](https://docs.slack.dev/apis/events-api/using-http-request-urls/) · [单聊事件](https://docs.slack.dev/reference/events/message.im/) · [回复消息](https://docs.slack.dev/reference/methods/chat.postmessage/)

成员在「我的工作区 → 账号设置 → Slack 账号绑定」领取十分钟有效的绑定指令，在企业机器人的单聊中发送。发送「新建 工作目标」建立项目对话，或用「切换 项目ID」接续已有项目。在同一 Slack 线程中回复「进度」「待办」或「补充 内容」。需要复查执行条件时，有权处理的成员可复制「待办」当前给出的指令。指令已过期时重新查询。附件、正式补件、成果审核和交付从链接进入原项目处理。解除绑定会清除原线程关联。

### 钉钉单聊入口

管理员在钉钉企业内部应用中启用机器人，选择 Stream 接收消息并发布给使用成员。API 配置 `PUBLIC_BASE_URL`、`DINGTALK_CORP_ID`、`DINGTALK_CLIENT_ID` 和 `DINGTALK_CLIENT_SECRET`。机器人编码与 Client ID 不同时配置 `DINGTALK_ROBOT_CODE`。服务主动连接钉钉，不需要另设入站回调地址。从本企业单聊接收带企业成员身份的文本消息。[钉钉 Stream 协议](https://open-dingtalk.github.io/developerpedia/docs/learn/stream/protocol/) · [机器人消息格式](https://opensource.dingtalk.com/developerpedia/docs/learn/bot/message/)

成员在「我的工作区 → 账号设置 → 钉钉账号绑定」领取并发送绑定指令。单聊发送「新建 工作目标」或「切换 项目ID」，接下来在原单聊发送「进度」「待办」或「补充 内容」。核对执行条件后，可发送待办给出的当前复查指令。附件、正式补件、审核和交付从链接进入原项目。会话回复地址失效后，可重新发送「进度」查看原项目的当前状态。

### 在 Slack 或钉钉调用已发布服务

在已绑定的单聊发送「服务」或「服务 关键词」，选取需要的服务 ID，再发送「发起 服务ID 工作目标」。预览列出目标、版本、调用次数、费用承担团队和最终确认人。十分钟内按提示在同一 Slack 线程或钉钉单聊确认，也可以从预览打开企业网页，对照原目标后附资料并确认。需要原件或包含第三方 Agent 的服务从网页核对并确认。

网页受理后可在原会话查「进度」和「待办」，两边指向同一项目。重复确认可取回已有的任务。更换目标、预览过期或服务换版时，在原会话重新发起并核对。用「新建」或「切换」进入其他项目时，当前尚未确认的服务预览失效。

### 发布和发起有必交项的服务

在「服务与渠道 → 发布可复用服务」选择已确认的协作方案，查看来源修订、拟发布及当前服务的必交项。核对这些文字可向服务调用方共享后发布。版本比较和回退会一并展示交付约定。已发布服务的执行步骤按固定清单接收本次工作要求，审核人在原项目按候选版本逐项核对。

缺项默认等待补齐。支持部分交付的服务可在网页发起时勾选「本次允许部分交付」，授权应用也可显式提交 `allowPartialDelivery: true`。单聊内直接确认采用缺项等待策略。审核时须为每个缺项记录接手人和继续条件，再由最终确认人固定本次交付清单。Open API 可在运行状态的 `deliveryCoverage` 查看必交项及核对结果，`humanActionUrl` 指向原项目。

### 飞书任务入口

为 API 配置企业实例的 HTTPS 外部地址 `PUBLIC_BASE_URL`，以及 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_ENCRYPT_KEY`、`FEISHU_VERIFICATION_TOKEN`、`FEISHU_TENANT_KEY`。群内定向消息另需机器人的 `FEISHU_BOT_OPEN_ID`。企业自建应用须开通机器人、接收指定范围的消息和回复消息的权限，并发布到试用成员可用的范围。把加密事件订阅地址设成企业实例的 `/api/channels/feishu/events`，订阅 `im.message.receive_v1`。[接收消息事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive) · [回复消息](https://open.feishu.cn/document/server-docs/im-v1/message/reply)

成员从「我的工作区 → 飞书账号绑定」领取指令，在与机器人的单聊中绑定。发送「服务 关键词」查找可用入口，再发送「发起 服务ID 工作目标」。机器人会列出服务版本、调用次数、费用承担团队和最终确认人，确认指令在十分钟内有效。使用同一单聊查询「进度」「待办」「成果」，发送「反馈 成果ID v版本号 具体意见」提出定向修改建议，打开项目链接审核及交付。群内须明确 @ 机器人；群回复只提供网页入口或操作指引。项目成员资格与审核权在平台核验。

需要随服务调用提交资料时，发起后在同一单聊发送一份不超过 96 KiB 的 UTF-8 TXT、Markdown、CSV 或 JSON 文件。需要选择汇总口径的服务使用 CSV。机器人会在预览中列出文件名，换附件后使用新的确认指令。确认后平台读取并固定原件，可发送「进度」查询读取状态。企业应用需要兼容的消息资源读取权限。[飞书消息资源接口](https://open.feishu.cn/document/server-docs/im-v1/message/get-2)

在单聊发送「待办」获取任务卡，或发送「待办文字」获取文字说明。使用「任务卡 项目ID」打开指定项目，群聊中须同时 @ 机器人，群卡仅提供项目入口。卡片中的成果待办会在登录后定位到对应版本。发起人与最终确认人是同一人时，单聊卡可以完整显示 320 字以内、未引用资料的规划答复，点「采纳这条回答」并确认。启用卡片里的采纳操作时，在飞书应用回调订阅中配置同一个 `/api/channels/feishu/events` 地址，并订阅新版 `card.action.trigger`，使用上文的加密和签名配置。[卡片交互](https://open.feishu.cn/document/feishu-cards/configuring-card-interactions) · [接收回调](https://open.feishu.cn/document/event-subscription-guide/callback-subscription/receive-and-handle-callbacks)

当第三方 Agent 的当前发布修订已验证补件，且正在等待输入时，在单聊用「切换 项目ID」打开原任务，再发「进度」查看步骤。通过项目链接核对问题，回到同一单聊发送「远端补件 #2 补充文字」，其中 `#2` 为实际的步骤编号。核对预览的接收方，按提示发送「确认远端补件 指令编号」，即授权一次费用待核算的调用。预览十分钟内有效，网页已经处理或问题版本变化时需重新核对。回执不明时打开原任务查看核对状态。

新多步骤协作中，已验证的远端补件问题会显示在对应步骤。其他就绪步骤可以继续；同时有多个问题时，在网页或飞书分别核对并确认各步骤的补件。远端响应无法确认时，先按原任务核对回执。

成员可以在绑定面板开启「审核单聊提醒」。机器人只发企业网页入口，登录后按当前项目权限展示有效待办。企业自建应用须具备发送单聊消息的权限。渠道未确认时最多自动尝试三次，之后成员可从绑定面板补发。管理员可在「企业管理 → 飞书审核提醒状态」核对通知数量。[发送消息](https://open.feishu.cn/document/server-docs/im-v1/message/create)

在「对话历史 → 我的待办 → 成果审核 → 提醒与协调」可查看负责人、版本及期限。团队内的管理员和项目发起人分别设置团队、项目节奏，默认时限为连续 24 小时，截止前 2 小时提醒，截止后 4 小时升级。升级到迁移 079 后，已有飞书绑定默认关闭主动提醒。迁移 080 会在项目退出审核时同步关闭旧时钟。

部署迁移 102 时，先更新全部 API 实例，再启用飞书新版卡片回调。已有账号绑定、项目上下文和文字回复由迁移保留。回滚到 101 时，先停用新版卡片回调，业务人员可继续从网页处理待办。

升级到迁移 059、060 时，先让全部对外 API 实例使用新版本，再开放关联修订。旧版本按每个项目单次交付读取，新版本为已有记录保留第 1 批编号。已产生多批交付时，回滚须使用支持多批记录的版本。

上线迁移 061 至 063 时，在新版本接管全部网页和 API 下载流量后开放分发。旧版本读路径不识别撤权决定。先前已交付且后来撤权的资料会自动进入待核对；维护窗口内用一个既有批次核对旧地址与预览权限。

升级到迁移 078 时，已有助手从发布代次 0 开始，原服务与项目仍按各自保存的修订执行。先让所有处理助手发布请求的 API 节点升级，再开放批次替换。旧 API 只检查修订的试运行结果，无法识别批次基线冲突。软件降级时应暂时关闭助手发布入口并保留批次记录。业务上恢复原模型可直接使用当前版本的批次回退。
