# Agent Alliance 生产化实施与验收

本阶段目标完整保留：多租户、分布式运行与故障恢复、完整 A2A 支持、Langfuse 集成、对应浏览器全链路测试，以及每个 Agent 独立模型凭据。上一阶段报告仅描述旧版本，不能作为本阶段完成证据。

## 必须完成的交付

- [x] PostgreSQL 持久化与并发事务；不再依赖单进程 JSON 文件作为生产存储。
- [x] 账号登录、工作区/成员/角色、租户隔离、工作区 API key 撤销与权限控制；UI 不索要模型 key 作为进入平台的条件。
- [x] 模型 endpoint 配置可复用，模型 key 只能属于单个 Agent；独立写入、保留、替换、清除与迁移，验证不同 Agent 请求分别使用各自凭据。
- [x] API 与 worker 分离，多 worker 任务领取/租约/心跳/fencing；故障接管、持久化节点 checkpoint、跨进程取消、超时、失败重试、幂等语义。
- [x] A2A 明确版本矩阵，覆盖发现、消息/任务、多轮、流式/订阅、获取/列举/取消、产物、push notification、扩展卡、transport 与认证协商；同时验证入站和出站，不将同步文本子集称作完整协议。
- [x] Langfuse 项目隔离、标准 OTel 摄入、trace 父子关系/模型用量/错误/版本/租户上下文、异步重试和去重、脱敏；真实本地 Langfuse 可见性验收。
- [x] 浏览器跨租户、独立 Agent key、服务编排、worker 故障接管、远端 A2A 生命周期、Langfuse trace 全链路测试。
- [x] Docker Compose 部署/迁移/备份恢复说明、真实测试证据与限制记录。

## 实施约束

已有数据不静默清空，不复用其他项目的数据库/容器。测试部署使用独立 Compose project 与端口。租户 ID 由已验证身份决定，前端传入的 workspace ID 只用于选择已授权成员关系。模型密钥和平台身份凭据是两类完全不同的秘密。

使用 PostgreSQL 事务状态存储承接现有 API，并将任务、租约、幂等请求和观测 outbox 作为独立表管理。运行定义在入队时冻结；已提交节点结果可恢复，未确定是否完成的外部副作用必须有明确重试策略，不能声称 exactly-once。

本计划只记录验收范围。只有实现、运行测试、浏览器与外部服务证据全部满足后，才更新完成状态。

最终执行结果见 [生产化验收报告](09-production-test-report.md)。
