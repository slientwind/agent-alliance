# Agent Alliance 产品方案

> 历史版本说明：本文件记录早期设计与验收。当前产品讨论以 [通用业务协作平台产品方案](10-product-blueprint.md) 为主线；已有实现的生产化技术记录见 [生产化产品与技术增补](07-production-architecture.md)。新产品方案不代表已有代码已经实现。

## 1. 定位与用户

面向应用开发者和平台运维的 Agent 能力平台。统一管理外部和托管 Agent，组合为服务，并为每次调用提供可追踪结果。第一版是可本地运行、可用 mock 全链路验收的单工作区版本。

开发者关注：快速创建、导入、试运行与 API 发布。服务设计者关注：节点协作、依赖关系、错误定位。运维关注：成功率、耗时、运行状态、失败原因、模型用量。调用方关注：稳定标识、认证、异步查询和明确错误语义。

## 2. 信息架构

工作台（指标、近期运行）→ Agent 注册中心（搜索、类型筛选、创建、编辑、停用、删除、试运行）→ 编排与服务（DAG 编辑、发布、调用）→ 运行与 Trace（筛选、详情、输入输出、节点时间线、取消）→ 模型配置（用户模型 endpoint、密钥、模型名）→ 开发者 API（端点、请求示例、API key）。中文界面，保留标准技术术语。

## 3. 用户流程与验收

### P01 外部 Agent 注册

粘贴 Agent Card JSON，检查 name、description、version、URL、skills 与协议类型。支持简单 HTTP JSON 适配器及明确版本的 A2A JSON-RPC 适配器；不宣称全部 A2A transport 和异步任务能力兼容。注册完成可试运行，卡片原始信息可查看。协议不支持时明确阻止保存/执行，不静默退化。远端错误进入 trace。

### P02 描述创建 Agent

填写名称、自然语言职责、模型配置；生成可编辑的 system prompt 草稿并保存。mock 模式用确定性规则生成草稿并标记；真实模型模式可调用用户配置的模型生成草稿。创建的 Agent 保存 prompt、版本、provider 引用，运行时向模型发送 system/user 消息。不会任意执行用户代码。

### P03 生命周期管理

创建、详情、搜索、编辑、启用/停用、删除。编辑增加版本。禁用后禁止新调用。被服务引用的 Agent 禁止删除，显示冲突原因；历史运行保留名称/版本快照。操作失败不能在 UI 中假装成功。

### P04 自带模型

配置名称、类型（mock/OpenAI-compatible）、base URL、model、API key。密钥只写入，不在读取接口返回。模型配置可用于多个 Agent。不能删除仍被引用的 provider。mock 模型无外部费用；真实模型由用户自行配置兼容端点。

### P05 编排协作与发布

创建服务草稿，添加节点，每个节点指定 Agent、依赖列表和可选指令。无依赖节点接收原始输入；有依赖节点接收上游输出。拓扑排序检查 DAG；同一层节点并发执行，下游在依赖完成后运行。节点失败使服务失败并记录原因。保存编辑与发布分离；发布冻结节点和 Agent 定义，修改草稿不影响已发布版本。服务得到独立 `/api/v1/services/{id}/invoke` 端点。可撤销发布；重复发布增加发布版本。

### P06 调用与运行

Agent 与服务都能从 UI playground 或 bearer API 调用。返回 run ID，客户端查询状态。状态为 queued → running → succeeded / failed / cancelled；终态不可再次取消。支持超时、取消传播、错误信息。mock 输入包含约定失败或延迟标记时可验证失败与取消，不影响正常模型模式。

### P07 监控与排错

指标来自真实存储的 run，显示总调用、成功率、运行中、平均耗时。按状态、目标和文本搜索，查看每次运行的输入输出、trace ID、错误、节点 span、开始结束、耗时和 token。不同节点具有 parent/run 关联。mock 数据和未知成本有清晰标记。浏览器轮询实时刷新，避免静态假指标。

### P08 Open API

管理接口与调用接口使用 bearer key，开发环境通过显式配置 key 启动。浏览器输入 key 建立当前会话。提供 OpenAPI 文档与 curl 示例。未认证 401、无效输入 400、缺失资源 404、引用/状态冲突 409。请求体大小限制与执行超时。第一版单工作区管理员 key；生产多用户、RBAC、配额另行交付。

## 4. 非功能验收

重启保留配置及历史；运行中重启将未终结任务标为 interrupted/failed，不伪装自动恢复。写入失败必须显式返回错误。并发访问通过 Go race 检查。卡片和模型 URL 仅允许 HTTP(S)，出站地址默认禁止私网，测试模式显式允许本地 mock。密钥不进入 API 响应或 trace。所有用户文本按文本渲染，避免 HTML 注入。

桌面布局清晰，窄屏可用；表单有 label、必填、错误提示、loading；删除前确认。空列表、空搜索、网络错误、运行失败均有可理解状态。

## 5. 验收业务场景

“客户反馈分析”：外部收集 Agent + 自建分析 Agent + 摘要 Agent。配置 mock provider → 导入卡片 → 描述生成 Agent → 编辑 → 独立运行 → 编排串行/并行依赖 → 保存发布 → API 调用 → 观察 trace → 故障注入 → 修复重跑 → 取消慢任务 → 删除引用冲突 → 撤销服务并清理。

## 6. 生产扩展路线（不作为已完成功能）

阶段二：OIDC/RBAC、多租户隔离、PostgreSQL、任务队列与 worker 租约、API key 范围和轮转、请求限额、幂等键、SSE、OTel 导出、审计。阶段三：人工审批、checkpoint 恢复、工具/MCP 沙箱、长期记忆、评测集、成本预算、告警通知、K8s/kagent 执行适配器。每项需独立安全和容量测试。
