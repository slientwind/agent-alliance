## 0. Codex 浏览器执行总则与测试环境准备

### 0.1 实例启动方式（任选其一，推荐方式 A 完整容器栈）

1. **方式 A：Docker Compose 生产拓扑启动（推荐，含断网沙箱与预览服务）**
   ```bash
   make configure
   docker compose --env-file .env.local \
     -f deploy/compose.yaml -f deploy/application.yaml up -d --build
   ```
   - 浏览器统一访问入口：`http://127.0.0.1:18485`
   - 初始管理员安装凭证：从 `.env.local` 读取 `BOOTSTRAP_TOKEN`

2. **方式 B：本机开发多进程启动（便于调试日志与挂载本地受控测试桩）**
   ```bash
   make infra
   # 分别在后台启动：make api / make worker / make tools / make preview / make web
   ```
   - 浏览器统一访问入口：`http://127.0.0.1:15173`
   - 配套全自动回归参考脚本：`make smoke`（参考 [`scripts/build-smoke.sh`](../scripts/build-smoke.sh) 与 [`frontend/tests/`](../frontend/tests/)）

3. **外部依赖准备说明**
   - **大模型供应商**：可接入真实企业模型（百炼 / 火山方舟 / DeepSeek / OpenAI 等），或在本地启动兼容 OpenAI `/v1/chat/completions`（支持流式 SSE、`tool_calls`、视觉与 `images/generations`）的受控 HTTP/HTTPS 测试服务，以便确定性复现「主模型宕机 3s Fallback」「预算触顶」等边界场景。
   - **外部 Agent / Webhook / 只读 SQL 目标**：可在宿主机或测试网段启动轻量 Mock 服务（A2A JSON-RPC、OpenAI-Compatible、Webhook 接收器、只读 PostgreSQL/MySQL 测试库），并在 `/admin/integrations` 出站白名单中显式放行测试主机与 CIDR。

### 0.4 全局浏览器验收红线（每条用例均须同时满足）

1. **零前端运行时异常**：全程监听 `page.on('pageerror')` 与 `console.error`，未预期脚本异常必须为 **0**。
2. **双视口布局完好**：在桌面端（`1440×900`）与移动端窄屏（`390×844`）下，`document.documentElement.scrollWidth <= window.innerWidth + 2`（无意外横向滚动条破版），模态框与抽屉支持 `Escape` 关闭且焦点正确归还。
3. **纯业务中文文案与零密钥回显**：任何表单报错（`role="alert"`）或空状态提示均不得出现 Go panic 堆栈、SQL 表名/列名报错或工程黑话；所有 API Key、Webhook Secret（除首次生成弹窗外）、OBO 令牌在刷新后重新打开表单均不得明文回显。
4. **SPA 深链刷新一致性**：在任意子路由（如 `/knowledge`、`/agents/studio/:id`、`/admin/monitor`、`/chat/:id`）执行 `page.reload()`，必须直接渲染原视图而不返回 HTTP 404。

### TC-001 空实例首位管理员初始化与凭证校验
- **前置条件**：全新空数据库启动实例，打开首页自动呈现 `初始化企业工作空间` 表单。
- **浏览器步骤（`Ctx-Admin`）**：
  1. 填写 `企业名称` = `星海智造集团`，`安装凭证` 填入错误字符串，`姓名` = `林予`，`邮箱` = `admin@alliance.test`，`密码` = `short123`（不足 12 位），点击 `创建首位管理员`；
  2. 将密码改为合规强密码（≥ 12 位，如 `AdminPass#2026!`），保留错误安装凭证再次提交；

  - 步骤 1 被表单最小长度拦截；步骤 2 显示清晰中文 `role="alert"` 错误提示且不建号；
  - 步骤 3 成功进入工作空间并自动弹出/展示首次工作空间配置引导；刷新页面后不再出现 `初始化企业工作空间` 入口。

### TC-002 首次工作空间一栈式引导（模型接入 + 6 档自动分配 + 扫描源 + 邀请码）

- **浏览器步骤（`Ctx-Admin`）**：
  1. 在 `接入模型供应商` 填写 `供应商名称`、`接口类型`（如 `OpenAI 兼容` 或 `阿里百炼`）、`HTTPS 服务地址`、`访问凭据`；

### TC-004 账号登录、登出与临时停用会话即时拦截
- **浏览器步骤**：
  1. `Ctx-Admin` 进入 `/admin/members`（或成员列表），创建/确认业务团队（`采购中心`、`电商运营组`）并将 `苏敏`、`周宁`、`陈默` 加入这两个团队；

  4. `Ctx-Admin` 重新为 `苏敏` 勾选 `允许登录` 并确认，`Ctx-Alice` 重新使用邮箱密码登录。
- **预期验收结果**：
  - 步骤 3 中 `Ctx-Alice` 原有会话立即失效退回登录页，使用原密码尝试登录被拒；
  - 步骤 4 恢复启用后 `Ctx-Alice` 可正常登录。

### TC-005 企业 OIDC 单点登录与强制 SSO 下的管理员应急登录

- **预期验收结果**：OIDC 授权码流与强制模式应急通道均符合预期，非指定管理员无法走应急登录。

### TC-006 全局导航外壳、双主题持久化、快捷键与 SPA 深链刷新
- **浏览器步骤（`Ctx-Alice` & `Ctx-Admin`）**：

- **预期验收结果**：所有深链刷新均 200 正常渲染对应组件，无白屏、无 404。

## Suite 02：三级空间管理（个人空间 / 团队空间 / 全企公共底座）与隐私隔离（TC-007 ～ TC-012）

### TC-007 侧栏空间切换器、对话列表隔离与输入草稿分空间暂存
- **浏览器步骤（`Ctx-Alice`）**：
  1. 打开 `/chat`，检查侧栏顶部 `getByLabel('当前空间')` 默认值为 `个人空间`，下方显示 `已继承全企公共底座`；
  2. 在 `个人空间` 输入框填入未发送草稿 `我的个人私密谈判备忘`，再发起另一条真实个人对话 `个人周报草稿整理`；
  3. 在 `当前空间` 下拉框切换至 `采购中心`：检查 `最近对话` 导航区不再显示 `个人周报草稿整理`，输入框自动变为空白，且输入框上方提示 `采购中心 · 使用当前空间知识与全企公共底座`；
  4. 在 `采购中心` 输入框填入未发送草稿 `采购中心比价需求`，再切回 `个人空间`、随后再切回 `采购中心`。
- **预期验收结果**：两个空间的未发送输入草稿各自无损保留、互不覆盖；发送消息创建项目时请求体准确携带当前选中的 `space` 与 `team`。

### TC-008 个人空间绝对私密红线校验（防管理员与同事越权窥探）
- **浏览器步骤**：
  1. `Ctx-Alice` 在 `个人空间` 创建对话 `个人薪资与职业规划私密记录`，上传一份私有笔记文件并获取回复，记录当前浏览器 URL `/chat/<privateProjectId>`；
  2. 切换到 `Ctx-Bob`（同团队同事）与 `Ctx-Admin`（企业全局管理员），分别在各自浏览器地址栏直接访问 `/chat/<privateProjectId>`，并尝试请求 `/api/projects/<privateProjectId>`；
  3. `Ctx-Admin` 打开 `/admin/monitor` 与 `/admin/members` 查看运行队列与统计。
- **预期验收结果**：
  - `Ctx-Bob` 与 `Ctx-Admin` 访问 `/chat/<privateProjectId>` 均被拒绝（403/404 无权访问），**绝不返回 `Alice` 的私聊正文或私有附件内容**；
  - 监控大盘仅聚合脱敏计次/Token（队列中无权查看标题处仅显示 `受限任务`），不暴露个人私聊正文。
