## 如何完成一件工作

| 用户所处位置 | 页面优先显示 | 用户可以做什么 |
| --- | --- | --- |
| 新对话 | 居中多行输入框，附件与 Agent 入口在左下，发送在右下，常用示例紧随其后 | 直接提问或描述交付物。能用现有资料回答的简单问题直接给出答案及依据，用户可明确采纳 |
| 需要澄清 | 一次问一个影响产出的业务问题 | 自由回复或点选建议。同一条对话保留最初诉求与答复 |
| 准备执行 | 简短说明交付物、用途、预计费用、修改方式和最终确认人 | 确认执行，或修改用途与分工。成员无需先认识各个 Agent；需要时才展开资料与负责人 |
| 正在执行或阻塞 | 当前进展、已完成数量、需要谁提供什么 | 离开后从历史继续；补资料、授权或处理异常后恢复。执行结束直接在对话中给出候选成果 |
| 查看、修改和审核 | 当前稿件、版本、来源以及可执行的动作 | 阅读成果，直接说“把标题改成……”。修改前核对受影响成果，修订后审核具体版本 |
| 完成交付 | 已确认的成果、版本清单和可下载文件。部分交付另列缺项、接手人及继续条件 | 轻量答复由发起人明确采纳。复杂成果包由最终确认人在桌面核对并固定版本 |

例如输入“帮我准备随行杯新品的内部评审材料”。助手询问用途，用户回复“给品牌组评审”。页面中直接出现方案；确认执行后，产品介绍和素材清单出现在原处。回复“把标题改成海蓝色随行杯”，助手说明正文可沿用、清单引用需要复核。只有版本被明确审核和确认后，才显示已交付。销售分析和培训任务沿用这套交互。

### 从业务需求创建生图助手

成员在输入框写下需求后，进入「Agent → 创建 Agent」，可以继续编辑这段描述。如果相同成果类型下已有名称相近或职责相同的已发布 Agent，折叠项列出匹配理由、职责、修订和费用承担方。可直接使用，或将其追加到正在编排的步骤。主动选用前仍可继续独立创建。选择图片成果后，仅列出有权使用的生图模型。存在一个适用的团队模型时预选其修订；有多个可选时由用户指定。创建前显示费用承担方和草稿共享范围。用户填写样图要求和视觉验收标准，验收人默认本人，可改为同团队的另一位成员。保存样例和授权生成图片是两个独立操作。

创建者或指定验收人可以稍后从「我的生图草稿与验收」回到相同修订。验收人打开样图、给出结论与依据，管理员才能发布通过验证的版本。回到输入框仍能继续原需求。若团队访问权变化，界面收起样图和相关操作，服务端重新核验对原件的读取和审核权限。[早期样图走查](evidence/rebuild-image-agent-entry/image-agent-sample-mobile.png)

### 在对话里寻找已有能力

搜索结果展示匹配业务词、已发布修订、实际产出及费用承担方。成员输入完整任务描述后可直接选择，也可先核对同类 Agent 的说明。从空白对话开始组合时，后续步骤的名称查询不会覆盖第一步的任务描述。单独搜索 Word、Excel 或 PNG 等格式时只显示能产出该格式的能力。在现有任务中单独搜索一个能力再新建，使用搜索描述填写 Agent 职责。仅输入格式时预选对应产出，用当前对话说明任务。在同一面板返回列表后，「继续未提交的配置」保留名称、模型修订和工具列配置，「创建 Agent」按当前需求重新填写。输入关键词的过程在当前可见的目录内完成；创建、验证和调用都有独立入口。[早期搜索走查](evidence/rebuild-agent-discovery/agent-picker-mobile.png) · [创建时的复用选择](evidence/rebuild-agent-discovery/agent-description-reuse.png)

### 在对话里补齐文件制作能力

例如成员上传收款明细，希望交付一份按区域汇总的 Excel。可以直接选用现有汇总 Agent，也可从「创建 Agent」选择「Excel 分组汇总」。点「从附件读取列名」后选定分组列和金额列，需要时再展开单位与筛选条件。如果只有一个可用团队，界面直接说明费用和草稿归属。成员另填一份允许共享的试算样例，打开生成的工作簿核对金额。关闭后，从「我的制作草稿与验收」可以继续。

如果是规划助手发现缺少能力，成员可以在原方案选择「用内置工具补齐能力」。试运行原件随这项缺口展示。管理员发布后，成员采用该修订，返回原业务目标和已选资料，核对方案后启动运行。[字段选择走查](evidence/rebuild-quick-tools/quick-tools-columns.png)

在规划授权区，指定交付文件格式收在折叠项中。直接描述成果即可发起规划。例如，附件为盘点明细，目标是逐行交付 Excel，可以在建议中看到工作簿格式、缺失操作和可复用修订。若输入是 Word 议程，目标只是回答签到时间，则按文本答复核对。使用者在同一任务中试做、审核及采用，不需要进入组织设置。

### 从输入框组合助手

在 Agent 选择框中打开「组合 Agent」，按任务顺序添加已发布修订。每一步展示版本和承担费用的团队，可提前或移除。单一团队时直接展示项目归属，组合涉及多个团队时可单独选择归属。点「使用此组合」返回原输入框，保留需求和附件，组合摘要可再次展开调整。发送后以相邻步骤接力作为初始依赖，后一步读取前一步的文本结果。图片与文档原件在成果审核中预览。项目的方案编辑器支持进一步分支与合并。确认界面列明本次授权的调用范围。

### 编辑方案时切换项目

在正式工作区，编辑交付目标、步骤依赖、资料或个人偏好后，页面显示草稿基于哪个项目修订。切换到另一个项目再回来，可继续编辑原稿。两个窗口同时修改时，后提交的一方能看到当前已保存的目标、分工和引用，选择沿用自己的草稿或放弃修改；沿用后仍需主动保存。刷新页面会清除本页草稿。

确认执行时，用户看到已保存方案的交付目标、最终确认人，以及每一步成果可用的修改方式。运行开始后，尚未提交的方案草稿可查阅和丢弃。新版本须重新勾选本次调用授权。

### 填写预算申请时切换项目

项目费用摘要显示「有预算申请草稿」。重新打开申请时，页面恢复原预算对象、阻塞任务、金额或次数、不足原因、剩余工作和替代方案。草稿只保留在当前页面，刷新、登出或检测到成员失去项目访问权后清除。项目已结束时可查阅、丢弃原稿。

平台按当前可申请范围与原修订核对。额度或任务修订变化时，申请人核对后才能提交。原对象已不可用时，申请人须重选预算范围或任务，也可明确改选「仅申请额度」。更换预算对象后需重新填写金额或次数。

仅在获得明确回执后清除对应草稿。回执中断时，可查看申请记录，再以原申请标识重试。旧版本已经受理时会提示核对记录。要另行申请可丢弃这份草稿后重新填写。

### 修订成果时切换项目

每份成果有独立的修订表单。文本保留修订正文和原因，Office 文件保留本页选定的文件、摘要和原因。遇到并发新版，表单展示当前正文或文件摘要，并保留自己的修改供核对。核对后可继续编辑文本，或下载当前原件、重新选择修订文件。离开审核阶段后草稿可查阅或丢弃；项目审核权限收回后清除该项目的本页修订草稿。

## 任务接续、能力接入与构建

11 月 23 日设计增补。报价比较、培训材料、研究报告和售后补证共用下述交互；对象名称、样例与审核规则随任务改变。可打开[采购任务交互样例](uiux/execution-review.html)，从缺一份报价信息走到补件、审核、查看旧待办和补发提醒。样例使用固定模拟回执；桌面网页支持缺项预览、原任务补件、部分交付审核、下载与通知补发。以下跨端、第三方接入与成员构建流程属于设计要求。[产品范围](10-product-blueprint.md#execution-experience) · [执行契约](11-technical-blueprint.md#execution-evidence-contract)

### 在原对话中接续一件未完成的工作

**委托与结果。** 发起人说「把三家供应商的报价整理成表，另列追问清单」。方案卡先显示两份必交成果、需要哪三份原件和谁确认。「确认执行」沿用原有预算授权。执行中的卡片把「已核对 2/3」放在首行，下方逐一列供应商、报价版本与缺口。业务成员点来源看证据，技术调用记录收在有权限的诊断面板。只有已经产出的文件可以预览。

| 状态及触发 | 用户看见的主操作 | 操作结果与退路 |
| --- | --- | --- |
| B 报价缺有效期 | 经办人点「补 B 的报价依据」，看到指定对象、已读文件和缺的字段 | 选择获准新版，确认本次使用范围，在原任务续跑 B。选错可在提交前返回；其他供应商保留原结果 |
| 已提交给外部 Agent，是否收到答复未知 | 显示「答复已提交，正在核对远端回执」，允许查看原答复 | 有原号时查询；无法自动核对则展示维护负责人。停掉后续工作仍保留在途核对入口 |
| 缺口清零，两个成果待审 | 审核人打开报价表和追问清单，逐项核对文件版本、结论与引用 | 可退回一项并填写原因；只有批准版本可进入既有最终核对。缺项但允许部分交付时，另列缺项与承担后续责任的人 |
| 多人从网页与飞书打开同一待办 | 只显示当前可操作的对象、范围和版本 | 重复点击回到原决定；同事已处理则显示其结果；版本已更换则从最新待办重新核对；无查看权限时收起原摘要 |
| 内部成果已交付，提醒失败 | 保留下载入口；另列「飞书提醒未送达」和最后尝试 | 有权成员点「补发提醒」，只更新递送记录。发送方只确认派发时显示「已派发」，取得送达凭证才显示「已送达」 |

**桌面与第三方渠道接续。** 对话和原件并排，点缺口定位对应证据。用键盘可操作附件、表格、审核和返回；处理结果由状态区播报。第三方消息中只显示渠道授权范围内的待办和必要摘要。复杂核对留在原任务，成员回到电脑浏览器时重新检查身份与版本。

**应用调用。** Open API 客户端显示任务号、等待类型和可进行的动作。需要人核对时向指定负责人展示项目入口；应用只读授权保留查询。若当前渠道无法承接审批，在授权网页留待办并说明接续位置。重复 API 请求、飞书卡和网页只消费一个决定。

### 维护者接入合作方 Agent

1. 从能力目录进入「接入第三方 Agent」，填写端点、责任团队与可用凭据引用。核对页并列「对方声明」和「本实例已验证」，分别列同步返回、长任务、补件、结果查询、取消及成果格式。
2. 选择一份可外送的试跑样例，预览发送资料、允许用途和试跑费用。运行中保留本地与远端任务引用。对方返回“需要有效期”时只向被指定的经办人发待办；凭据失效交连接负责人。
3. 验收人下载实际输出，核对字段及引用。无法查证外部结果时展示「结果待核对」，提供查询或转人工；声明支持但未测试的动作只列在维护视图。发布时确认对成员可见的工作范围、修订和费用归属。
4. 成员回到原方案看到「已验证：报价摘要；异步取消待验证」等业务说明，可采用合适修订或返回选择。更换端点或授权范围后，维护者只对受影响操作重新验证。

### 成员把一次成功任务做成团队 Agent

从已采纳的报价任务点「存为 Agent 草稿」，或在能力选择器点「创建 Agent」。预填职责和交付清单；成员逐项选择可以带入的能力修订及可共享的脱敏样例。原件、凭据及无权共享的对话不进入模板。创建者指定维护团队、缺项时向谁提问、验收人和费用承担方。

预览用「输入一份缺有效期的报价 → 出现缺项 → 补件后生成两份成果」展示本次样例的完整轨迹。试跑与保存分开。只返回一份成果时，停在「1/2 份符合」，展开可见未达条件；可在同一草稿修订配置后重新试验，并保留前次结果。通过后按原有权限提交发布，成员在新工作里明确选用已发布修订；发布不自动替换进行中的任务。

### 交互评审脚本

- 给采购经办人一份缺字段报价，让其指出「哪一家、缺什么、谁来补」，再完成补件。核对只重算 B，且能从结果返回依据。
- 给审核人一张旧飞书卡，从网页先处理有效版本，再打开旧卡。核对当前决定只保留一份；随后撤权，旧卡中的原文不可见。
- 给能力维护者一个仅通过同步文本的远端 Agent，让其判断能否承接次日才返回的询价。维护页能指出缺哪一项验证，成员候选结果与已验证范围一致。
- 给创建者一次已验收培训任务，要求做成团队 Agent。检查跨项目样例授权、失败试跑原因、发布版本和新任务复用，并确认旧任务仍引用旧版。
- 核对「已交付，提醒未送达」：成员应能下载批准版本且只补发原通知。用单独的运行、决定与通知计数判断，避免仅凭提示文案判通过。

## 桌面对话如何显示运行、等待与交付

以[全景中的执行和投递边界](11-technical-blueprint.md#approved-platform-engineering)为准。同一工作在左侧历史保留入口，中间对话显示当前决定和主操作，右侧按需展开来源、版本和成果。新对话沿用居中输入。后台组件名称、调用参数和诊断日志收在获准的维护视图。布局、字号、行宽与状态样式沿用[桌面网页设计依据](uiux/desktop-web-references.md)。

| 此刻发生了什么 | 对话里的文字与主操作 | 界面根据什么更新 |
| --- | --- | --- |
| 发起、已受理 | 发送后显示「已收到」，工作开始后显示正在办理的对象。重复发送可回到原任务。 | 提交回执给出同一消息与运行号，随后消费运行状态。切换对话或关页后仍可在历史中接续。 |
| 正在生成、中途断线 | 支持流式回复时逐段显示当前草稿。断线提示「连接中断，正在恢复」。需要停止工作时由用户点「取消执行」。 | 按实际尝试和偏移合并文本，按事件序号去重。重连使用游标，游标过期则重取授权草稿并刷新业务状态。权限变化时收起受限内容。中断草稿与下一次尝试分开显示。 |
| 模型已生成，候选待确认 | 调用记录显示「正在核对模型回复」。已有草稿标明等待核对。通过后从成果区打开候选；原回复截断时按当前步骤显示阻塞或人工工具选择。 | 当前发行版的适用文本步骤读取原尝试检查点；检查点期间重连恢复草稿及核对状态。候选出现以业务提交为准。 |
| 缺资料、规则失效或待授权 | 显示「还缺 B 的报价有效期」或「团队规则已失效，等待负责人确认」。卡片列对象、原因、经办人和可做的动作。按实际等待范围说明「其他步骤继续」或「任务等待补件」。 | 从服务器读取等待范围、待办修订及当前授权。提交前复核版本，已被同事处理的卡片打开最新决定，失去查看权后收起受限内容。 |
| 合作方提出补件问题 | 当前待办显示问题、接收方、拟发送文字和预计费用。费用未知时单独说明并请求本次授权。经办人选择「提交补充资料」。入队显示「待发送」，派发后显示「等待合作方回执」。 | 补件绑定原任务和当前问题版本。服务端确认派发效果未知时显示「补件回执待核对」，且保留已提交状态。有获准查询能力时提供「核对原任务」。收到新问题后展示新待办；其他窗口完成旧问题后刷新原卡片。 |
| 请求已派发，远端效果未知 | 显示「任务暂停派发，正在核对合作方回执」。保留当前获准查看的候选、上次联系时间和负责团队。有查询能力时提供「核对原任务」，否则呈现人工核对入口。 | 远端受理、业务结果和取消回执分别映射。已发取消请求时显示「已申请取消」，最终显示以查实的结果为准。 |
| 有成果待核对 | 右侧候选给出已覆盖对象、来源、版本和缺项，例如「已核对 2/3，B 缺有效期」。必交项缺失时可预览，主操作是补件。 | 读取对象级覆盖和审核权限。只有原委托允许部分交付时显示相应操作，由审核人逐项接受、登记缺项、后续负责人及继续条件，再交最终确认人。[交付规则](10-product-blueprint.md#delivery-decision) |
| 已部分交付，随后补齐 | 已发布版本显示「已部分交付」，保留文件下载和当时的缺项清单。经办人从同一任务打开仍待补的对象。 | 补件产生新候选。新版本经审核和最终确认后增加一份交付清单；历史下载仍指向原版本。缺项的负责人和继续条件可定位到具体记录。 |
| 已交付，渠道提醒未送达 | 对话保留「已交付」与下载入口。递送行显示「飞书提醒未送达」，有权限的人可点「补发提醒」。 | 交付版本来自正式清单，提醒状态来自独立投递记录。补发沿用原通知。 |

**同一工作同时有多个待办。** 运行仍在推进时，对话按步骤与对象列出各自待办，已完成的分支继续在成果区显示。表单草稿按原运行、步骤和问题修订保留。成员从飞书原任务的「进度」进入，按已验证的入口处理。提交一项后保留其他未处理项。显示「已提交，等待回执」的待办保留本次确认内容。出现新问题时，旧卡显示原决定并定位新问题，用户按新内容确认。整次运行暂停时，对话顶部显示原因与恢复操作。具体展示按服务端返回的等待范围决定。[等待范围与当前实现](11-technical-blueprint.md#execution-wait-scope)

**在两个文本 Agent 中选择。** 方案编辑器在执行业务步骤内显示备用修订和负责选择的前置步骤。确认页并列显示候选，标明第三方及可能发送的已授权输入。工具或 Agent 未选定时，原任务显示当前可选择的修订，获准经办人从同一待办继续。飞书展示待办所在步骤并返回原项目。执行详情可核对实际选择、执行者和费用。[验证记录](13-acceptance-spec.md#approved-platform-evals)

**同一工作换渠道。** 飞书、Slack、钉钉按已验证的操作呈现当前身份有权查看的摘要、待办和接续入口。原件比对、复杂成果包终审回到桌面原项目，重新核对登录身份及版本。签名 Open API 通过运行状态事件和查询读取同一业务对象。各渠道显示自己的送达结果。桌面用键盘能依次进入缺项、来源、处理动作并回到原消息，状态区播报等待、完成及错误，避免每段流式文本都打断阅读。[交互验收判据](13-acceptance-spec.md#approved-platform-evals)

Slack 入口在工作区账号设置中提供绑定和解绑。成员从机器人单聊新建或切换项目后，在同一线程查询和补充对话。需要复查执行条件时，「待办」给有权成员当前指令。旧指令会提示刷新，资料与成果处理从项目链接接续。0.1.44 已通过本地协议和浏览器走查，企业工作区按 EA07 另行验收。[操作说明](USER-GUIDE.md#slack-单聊入口)

钉钉账号绑定沿用同一工作区面板。成员可在机器人原单聊接续上一次关联项目，「待办」提供当前可复查的步骤，资料与成果处理仍从原项目打开。钉钉单聊以会话关联，Slack 以线程关联。[钉钉操作说明](USER-GUIDE.md#钉钉单聊入口)

**同一工作重新打开。** 保留当前对话和已获准的候选位置。新投影到达时，从服务端重查正在处理的卡片、成果和原件。若同事已补件，卡片显示生效的决定，可跳转到当前待办或候选版本。若读权限已撤回，清除对应草稿、原文和预览，把焦点移至权限提示或仍可打开的任务入口。客户端保留当前用户尚未提交且仍获准处理的表单内容。提交返回冲突时说明需核对的变更。[会话接口](11-technical-blueprint.md#web-session-projection) · [跨模块验收](13-acceptance-spec.md#platform-handoff-evals)

<a id="affected-branch-interaction"></a>

### 规则失效时核对要重做的步骤

首次调用前，已获准的负责人可在原待办核对并确认可用规则版本。已经用过失效规则时，对话保留原任务位置，待办主操作改为「核对重做范围」。打开后按任务顺序显示「需要重做」「沿用已完成成果」和「继续未完成的步骤」。每项在获准范围内显示受影响的对象、相关依据及可沿用成果的确切版本。替换规则显示修订及适用范围，确认前展示新增调用上限与费用承担方。

确认后，原对话显示关联批次的进展，沿用的成果仍可在右侧打开；因规则失效收起的旧正文不进入新的上下文或预览。若出现新的规则修订、授权变化或并发处理，卡片刷新并让经办人核对当前范围。若有调用待核对，保留原回执入口并说明下一步由谁处理。飞书卡定位原待办，范围比较和授权确认在桌面完成。[技术契约](11-technical-blueprint.md#rule-branch-recovery) · [走查用例](13-acceptance-spec.md#rule-branch-evals)

偏好或规则导致未审核成果失效时，成果卡片显示「待重做」，给出需要恢复的原因。发起人在原任务打开重做清单，先看可沿用的版本、需要重做的步骤和调用上限，再确认。其他项目成员看到负责处理的人。已经审核的有效历史版本仍可从成果历史查看。

<a id="build-memory-controls"></a>

### 构建、记忆与授权如何回到当前任务

成员可在原对话创建或选用草稿，在独立构建工作台维护职责、固定依赖、样例、试跑和发布。返回任务时定位到原能力缺口，选择已获准采用的发布修订。记忆管理提供单独的个人偏好、团队规则及适用范围视图；任务内保留本次实际采用的条目与来源引用，供成员核对结论。

| 入口与目的 | 默认可见内容 | 状态变化后可进行的操作 |
| --- | --- | --- |
| 「Agent」搜索和采用已有能力 | 适用工作、经验证的输入与成果、可选修订、所有者及费用承担方 | 当前项目缺权限时给授权待办。远端能力只开放已验证操作，具体声明、连接状态和回执进入维护视图。 |
| 「创建 Agent」或「存为 Agent 草稿」 | 职责、样例、固定依赖、试跑费用、验收项及范围。发布申请显示待核对的依赖版本、验收结果与受众 | 草稿有冲突时保留本次编辑并显示当前版本。发布清单或证据变化时指出具体差异，回到相应检查后更新申请。已受理任务继续显示实际绑定的修订。 |
| 「发布历史与恢复」 | 团队管理员在同处对照当前和目标修订的模型、Skill 与验收记录 | 填写恢复原因后提交。发布代次或依赖已变化时，刷新历史与验收证据。恢复成功显示新发布修订，已确认项目仍按原绑定展示。 |
| 「协作模板」核对组合构建 | 模板详情显示构建清单与逐步骤可用状态，版本比较显示新版清单 | 申请发布和确认发布前处理已失效的依赖。已创建的模板项目可在方案中明确选择新的可用能力，保留步骤目标。 |
| 「协作模板」带入必交项 | 保存模板时编辑适合复用的条件。新对话按业务步骤显示必交项，缺项默认等待 | 升级模板时并排核对原方案与新版条件。删减或换绑须确认；部分交付由本次项目单独选择。 |
| 「本次使用的依据」查看短期工作集与来源 | 显示本轮采用的资料版本、原文位置、已经核对的对象、待补项及适用规则 | 来源变更或撤回后收起受限正文，指出受影响成果及经办人，按当前授权补件或恢复。 |
| 长对话规划 | 使用历史摘录时在建议下提示保留了完整的最新用户消息。相关的早期摘录可在建议中展开，按需定位原消息。 | 用户可在当前对话重申会影响交付的条件。引用内容变化或资料撤回后，关联答复与摘录按当前范围重新核对。 |
| 「个人偏好」管理跨任务信息 | 成员明确保存内容、适用 Agent 和有效期，方案显示所选偏好及修订。只在方案包含适用 Agent 时提供该偏好。团队规则由有权者发布。 | 原限定范围移出方案时，提醒移除偏好或恢复对应 Agent。运行中显示失效影响，未派发的步骤省略无效的限定偏好，已使用过的候选按原依据核对。 |
| 「调用详情」或「企业管理」核对异常 | 受权维护者查看构建修订、实际尝试、远端回执、耗用及等待原因 | 未知回执先查询原号，无法查证时可交有权者处理。个人对话和维护视图按各自权限隐藏已撤权正文。 |

在对话内调整草稿、关闭订阅或尝试补件时，保留原任务位置与已处理对象。发生签名、授权或版本冲突时，从服务端刷新当前状态，错误文案说明可继续的操作以及责任人。候选预览、已部分交付、已交付与通知状态分别使用文字和可聚焦操作。[模块责任](11-technical-blueprint.md#approved-platform-engineering) · [构建、记忆与回执验收](13-acceptance-spec.md#approved-platform-evals)

构建侧栏优先显示适用工作、样例验收、结果与发布操作。依赖清单、Skill 修订、失效证据和外部连接证明按需展开。执行侧栏先显示「本次使用的依据」和候选版本，允许在成果、原文及相关待办之间往返。相同动作在桌面对话或企业 IM 中提交后，两边都以原决定更新；复杂成果确认只在桌面工作区执行。对同一任务做界面走查时，分别检查报告给业务用户的结果和维护者可见的回执。

### 主操作怎样随任务、身份和渠道变化

对话先呈现当前业务对象、已取得的结果和用户可做的下一步。右侧面板保留可审查的资料与候选，构建工作台保存发布前的依赖与证据。若同一运行有多个待办，在对话中逐项呈现，点击某项后才切换对应处理面板。用户收起面板可回到原卡片，切换步骤时保留当前身份获准的未提交输入。

| 当前任务 | 桌面主操作与信息层级 | 第三方入口及服务端决定 |
| --- | --- | --- |
| 委托尚未确认 | 输入区为主，方案展开后先看要交什么、必需依据、操作上限和人员。Agent 来源及固定修订收在能力详情。 | 已接入的 IM 可提供任务入口。网页与签名应用提交后都从同一运行读取实际受理状态。 |
| 工作在推进或等待 | 对话显示「正在核对哪一项」或「还缺什么」。切换到右侧的依据和候选时保留当前步骤。按运行控制权呈现取消或暂停。 | 飞书等已验证渠道可呈现待办、摘要与接续链接。重连用授权快照恢复；依赖和待办修订由服务端返回。等待、断线和取消各有可辨识文案。 |
| 要补材料或核对远端回执 | 先列对象、问题及负责人，再呈现授权范围、接收方和费用。收到旧回执时刷新原待办。远端状态未知时，主操作是「核对原任务」或「交人工核对」。 | 在渠道支持时按原待办直接应答。需检查外发原件或确认敏感资料时进入桌面原任务，重查当前授权。 |
| 审查候选与交付 | 默认显示对象覆盖与未满足的必交项。选择某一项可定位原文、候选版本和对应审核决定。部分交付被允许时才出现逐项接受及缺项责任表单。最终确认后展示清单和下载。 | IM 显示有权查看的摘要并返回网页终审；Open API 按服务支持范围给出候选和待办状态。送达失败显示在通知记录中，补发沿用该交付版本。 |
| 试跑并发布 Agent | 依次看到样例、当次实际装载的 Skill 和试跑结果、待补验收、发布范围。仅对具备发布资格的维护者显示对应提交动作。当依赖或证据变化时，定位需重验的样例。 | 团队从已发布目录采用能力。正式发布、版本差异、临时停止和凭据管理在桌面构建或维护界面进行。 |

信息密度以[网页对照的布局和字体规格](uiux/desktop-web-references.md)为基线。首页只展开起笔所需内容，执行中把进度与等待放回对话，审核时再展开资料和版本并排比对。文字说明状态，颜色只辅助定位。后台的运行号、模型尝试、预算和差错原因在有权查看的调用详情中展开。以界面原型走查操作顺序，以服务端事务及事件流判定状态。[角色与完成条件](10-product-blueprint.md#work-decision-rights) · [联合走查](13-acceptance-spec.md#architecture-review-runs)

### 在原对话确认工作并接续

从一条委托打开方案时，先呈现交付物、需要核对的对象、资料范围、调用上限、费用承担方和最终确认人。Agent、Skill、规则及修订在对应步骤内展开。成员选「确认执行」后保留原对话位置。界面以业务记录确认任务是否已受理，工作区、消息入口和已配置的应用从同一任务接续。

| 用户动作 | 应看到的回执和下一步 |
| --- | --- |
| 确认后网络中断 | 原方案显示「正在核对是否已受理」。查到原决定后定位原任务。需重新确认版本、预算或来源时，跳回发生变化的项目，保留仍可编辑的输入。 |
| 同一待办已在其他入口处理 | 网页和企业 IM 都显示当前已生效的决定及对应对象。存在新待办时提供当前入口。原表单仍有授权的未提交内容可保留，过期操作停在核对状态。 |
| 桌面对话中需要补材料 | 卡片先写清缺哪个对象、由谁补和补完会接续哪一步。已完成的独立步骤保留。飞书仅对受支持的正式补件提供对应动作；Slack 和钉钉的当前文本补充记录到原对话，正式补件从原项目进入。 |
| 从企业 IM 打开桌面原任务 | 恢复到具体待办、候选或交付的可见位置。身份或职责变化时先显示可读状态及处理方式，再根据授权打开材料。仅有项目链接时定位项目当前进展。 |

## 导航与权限

- 宽屏对话保留左侧历史导航。工作区收窄时，侧栏可折为图标并随时展开。历史支持新建、搜索或继续工作，条目显示任务标题和当前状态。
- 「我的待办」按成果审核、预算追加和能力授权筛选。选择「成果审核」后按当前身份展示可审核的成果、分配的反馈和最终交付确认。每条标出项目、步骤和成果版本，可直接定位原文。成员打开旧待办时先读取最新项目；如果同事已处理或转交，页面显示当前状态。
- 「预算追加」按当前预算负责人归集多个承担团队的金额和调用次数申请。预算负责人可查看申请时与当前额度、追加后的额度和申请理由，直接批准或拒绝。项目成员可见标题并进入项目，其他负责审批的成员按项目编号辨认申请。打开旧入口会读取最新结论；预算负责人转交后由接任者处理。
- 输入框旁的「Agent」优先显示搜索框和「创建 Agent」，同一页提供组合和模板。试运行前显示费用承担方与估价状态。能力库、服务与渠道可从「我的工作区」进入，授权事项收在「协作与授权」，登录身份和飞书绑定收在「账号设置」。当前任务缺少能力时，直接在方案内进入绑定与试运行，随后返回该对话。
- 资料、决策记录、费用和运行详情收在当前对话的「对话详情」。通知与阻塞消息链接到相关任务；消息中的审批按钮须核对当前权限和版本。
- 管理员与普通成员共享首页。「企业管理」默认打开「模型与 Agent」，用户资料和用量从「用户与监控」互查，团队、部门及范围授权位于「高级设置」。默认原型使用普通用户视图，通过页面查询参数 role=admin 可评审管理员入口。正式鉴权及统计口径见[产品第25节](10-product-blueprint.md#enterprise-instance-admin)。

### 企业管理中的运行监控

默认查看近 30 天的企业汇总。选择近 7、30 或 90 天，再选发起成员或应用，数量与费用一起更新。执行完成、能力样例检查通过、成果版本审核通过、简单回答已采纳、正式交付批次分别显示。有阻塞或未核实费用时，相应数字加粗。展开「统计口径」可查每项归给谁、按哪个时间计算。窗口读取失败时显示当前周期的错误；切换范围可重新读取。

运行监控和获授权的范围汇总均可展开「运行状态分布」。折叠时显示执行中和失败数，有失败时加粗数量。暂停、等待回执、普通阻塞各占一项。收到远端明确的失败或拒绝回执后，用户从当前运行的控制表单填写原因，确认是否结束。其他分支仍有待核对的调用时，平台保留核对入口。

从成员资料进入用量，大盘保留日期和团队筛选，再按成员显示运行与费用。单团队实例直接显示企业范围，可按成员或应用筛选。返回资料后可展开账号变更记录。当前成员行以冷灰底、黑色左边线和加粗姓名标识，历史记录和常规计数保持常规或中等字重。变更表单加粗将生效的角色和登录状态，列出需交接的项目及待审版本数量。成员在自己的工作区查看未读账号通知，逐条标记已读。

管理员从「管理汇总授权」明确选择企业全域、团队或部门，并决定是否开放该范围的用量与费用。成员从自己的工作区打开「获授权的管理汇总」。先前所选范围撤销或到期后，旧数据收起；有其他范围时，由成员明确选择要查看的范围。管理员可核对最近 50 条已结束授权的原授权人、原因和结束时间。

在获准的团队或部门汇总内，成员可展开「成员与任务明细」，按发起人名称筛选或直接进入全部任务。任务以编号标识，突出当前状态、阻塞类别及最终确认人。逐任务费用在获准时显示。打开明细后固定统计周期，翻页保留所选发起人；管理身份和汇总导出均不授予明细访问权。

选中企业全域时表单说明覆盖所有团队、部门和无部门记录的历史活动。管理员自己持有全域导出权时，可在运行监控的全部发起人视图准备导出；切换到个人或应用后，收起全域导出表单。

导出权可以单独授予或收回。成员打开导出表单后先核对组织范围和起止时间，再填写接收方与用途；有费用查看权时可主动勾选费用。生成后由申请人下载 JSON 文件。收回导出权后，该成员仍能在页面查看获准的汇总，已签发的下载立即失效。再次开放导出时需要重新生成文件。

在持有财务导出权的范围内，「准备导出逐笔费用」会打开包含范围、起止时间和文件字段的表单。可以按本地时间缩短周期，再填写用途与接收对象。财务文件单独列在「查看近期费用文件」中。管理员切换到单个发起人时，收起企业全域财务导出入口。

### 对话内的跨团队授权

「跨团队能力授权」默认折叠。展开后，白底列表把承担团队、资源、操作、单次估价、已用次数和有效期逐行对齐。待资源授权、待预算确认或次数用完时，使用实心菱形和粗体文字。已批准和已关闭的状态采用空心圆及常规灰字。提供方从「我的待办 → 能力授权」按当前职责处理资源或费用决定，回到对话即可继续原方案。[桌面实屏](evidence/rebuild-project-agent-grants/project-agent-grant.png) · [早期窄屏走查](evidence/rebuild-project-agent-grants/project-agent-grant-mobile.png)


### 选择项目团队和能力归属

新对话的大输入区提供消息、资料和 Agent。只有一个可用团队或有有效默认团队时直接采用。已加入多个团队的成员可从「我的工作区 → 协作与授权」打开「更改项目归属」。无默认且有多个可用归属时，首次发送展开并聚焦归属选择，保留需求与附件，选择后再次发送才创建项目。有多个可用团队且当前采用非企业默认归属时，输入区显示归属名称，点名称即可改选。同一页面提交普通任务后，有有效默认时下一次回到默认归属，无默认时沿用已选归属。刷新后重新判断。临时选用 Agent 时，按本次选择确定项目归属及费用，移除或用完该选择后恢复普通对话归属。退出原团队后保留草稿，重新选择有效归属后才能发送。

候选列表按已写需求与发布版名称及职责的匹配排序，显示匹配词，保留其他可选能力。用户点选后才带入草稿。

从输入框选择已发布 Agent，或从能力库点击「使用…开始对话」，均带回具体发布修订、费用承担方和原来的需求。能力库仅在新对话尚未选择 Agent 时提供此快捷操作。所有可见能力均属于唯一已加入团队时，归属在列表顶部统一显示。

输入区在用户写出可匹配的任务描述后显示至多两个 Agent 按钮，用粗体标出名称并列出命中的任务词。多团队时显示候选归属。推荐和点选都沿用现有输入区，不打开额外页面。内置模板从 Agent 列表打开，成员可在可用的发布版本下点「用于当前对话」，回到原需求和附件。

能力库登记工具和外部 Agent 的表单分别提供「归属及费用承担团队」。外部能力的授权卡还展示原任务的查询、取消范围、每轮核对时限和失败重试次数，预算负责人可在确认承担费用前阅读。[外部能力审批实屏](evidence/rebuild-borrowed-connectors/borrowed-finance.png)


### 从对话选用编稿与排版能力

单一团队的首次配置页直接写明费用承担方。课件任务在对话输入区提供「编写分页提纲」，同团队有已发布文本能力时另提供「让 Agent 编稿」。后者展示候选的实际名称、版本及能力说明，选择后在输入区显示两步顺序，可调整组合并附加原件。执行前仍需确认方案与用量。网页审核可打开 PDF 预览，反馈面板支持按页填写标题和正文；旧版预览与已审核的可编辑原件分别保留。[编稿选择走查](evidence/rebuild-course-deck/course-writer-picker.png) · [早期预览走查](evidence/rebuild-course-deck/course-review-mobile.png)
